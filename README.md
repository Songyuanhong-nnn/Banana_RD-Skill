---

## 先说清楚：它不是什么

v2.0 曾写"适用于所有领域"。那句话违反了这个 Skill 自己的第 5 条原则——**出现"所有"就必须查反例**。反例是现成的，所以 v2.1 把它撤了，换成一张诚实的账：

| 适配度 | 领域 | 为什么 |
|---|---|---|
| **强** | 科学机制、技术选型、历史史料 | 结论落在一手层，且**证伪路径也公开**（重复实验、源码+实测、史料批判） |
| **中** | 法律、金融/商业、政策 | 强在条文/披露/文件检索，弱在个案事实、内部数据、反事实 |
| **弱** | 医学临床决策、私有系统故障、多主体博弈 | 决策变量是本次个体/当前局面的私有数据，检索拿不到 |
| **不适用** | 数学证明、审美判断、实时决策、未公开数据 | 演绎问题、无可证伪 claim、时间预算不允许、证据不在公开域 |

完整判据、每个域的"最容易被误导之处"与降级路径见 [`references/domain_fit.md`](ai-sq-universal/references/domain_fit.md)。

## 它保证什么、不保证什么

**保证**：结论可追溯（ID + 原文句 + 等级）；范围被检验（对谁成立、何时不成立）；**因素被枚举**（不是挖到一条链就交卷）；停止有理由（能区分"查完了"与"查不下去了"）。

**不保证**：可执行的专业决定；一手数据；演绎结论；秒级答案。

## 核心：为什么需要三套覆盖机制

v2.0 只有九层追问链，它是**纵切**——把一个对象顺着一串问题挖到底。但真实问题通常是"很多因素共同作用"，纵切跑完可能只挖了三条链，另外六类因素根本没被想到过。

**层数深 ≠ 覆盖面全。** 而且纵切还有个更隐蔽的盲区：它不知道"客户会问什么"。所以三套机制各管一层：

```
纵切：九层追问链 ──────────────→ 深（一条线挖到底）
面覆盖：14 维总纲（D1–D14）────→ 全（决策者会问的问题面）
横切：因素空间（9 轴 + 量级）───→ 细（因素别整类漏掉）
切面：分层矩阵 ───────────────→ 准（同一因素在不同情境反向）
接入：交互与混杂（15 个模式）───→ 真（因素不独立）
验收：覆盖饱和（六条判据）─────→ 可核（"全面"不再是形容词）
引用：引用到句（定位 + 原句）──→ 可查（每条结论能 30 秒复核）
```

### 1. 复杂度分级 L1–L4：先定档，再决定展开多少

| 档 | 结构判据 | 必做检查 |
|---|---|---|
| **L1 单链** | 单一主因→主果，且已做分层/交互检查未发现反号 | 九层链 + 反例，不建因素空间 |
| **L2 多因素** | ≥3 个相对独立因素，且检验未发现反号 | 因素空间 + 量级 + 共线/混杂初查 |
| **L3 交互/异质** | 分层后反号、联合效应非可加、阈值/非线性、案例间机制不同 | L2 + 交互矩阵 + 分层矩阵 |
| **L4 动态系统** | 因果图有双向边、双向时间证据、已知时滞、regime shift | L3 + 因果图 + 时滞 + 情景分析 + 模型局限三字段 |

五条硬规则里，两条最关键：

- **档位与因素数量正交**：因素多但全线性 = L2；因素少但有强反馈 = L4。别把"因素多"当"复杂"。
- **档位 ≠ 完成度**：档位决定"必须做哪些检查"，预算决定"这次做完几项"。预算不足**不降档**，把未完成项标 `unchecked` —— 降档会让"没查"悄悄变成"不需要查"。

还有一条专治自欺：**"没查到反号"不等于"没有反号"**。未做分层/交互检验就没有资格定 L1/L2，按高一档处理并在 `gaps` 留痕。

### 2. 因素空间：按轴枚举，不许凭记忆

九轴机械过一遍，每轴要么有因素，要么写"空，理由"。留白与"确认没有"是两件事。

| 轴 | 最容易漏 |
|---|---|
| 时间 | 横断面数据当因果，看不见时滞 |
| 空间/层级 | 生态谬误（群体结论套个体） |
| 主体 | 只算客观因素，漏掉"谁在决策" |
| 物质/资源 | 把资源约束当成"其他条件不变" |
| 规则/制度 | 忽略制度变化导致效应反转 |
| 信息/认知 | 假设主体全知理性 |
| 技术/工具 | 忽略技术代际差异 |
| 环境/外部冲击 | 把一次性冲击写成结构性原因 |
| 反馈/动态 | 静态框架看不见动态 |

每个因素必须带 `role`（必要/促进/阈值/调节/混杂）、`direction`、**`magnitude`**、`magnitude_basis`、`proxy`、`how_to_test`。

**量级是硬要求**：`dominant` / `major` / `minor` / `unknown`（unknown 必须写原因）。禁止"上述因素都很重要，需综合考虑"——那句话的信息量为零。

### 3. 交互与混杂：15 个必须主动比对的模式

见 [`references/complexity_patterns.md`](ai-sq-universal/references/complexity_patterns.md)：混杂、中介、效应修饰、交互、对撞、Simpson、生态谬误、阈值、反馈、时滞、路径依赖、等效路径、代理误差、选择偏差、相变。每条含"如何识别 / 必须追问 / 检索线索 / 常见误判"。

输出必须含 `checked-none`——**否则读者无法区分"查过没有"与"根本没查"**。

### 4. 覆盖饱和：把"全面"变成可验收

报告 §14 六条判据，缺一条就不许说"已系统覆盖"：

1. **轴覆盖**：9 轴走过，空轴有理由
2. **量级覆盖**：每因素有量级，unknown 有原因
3. **饱和**：连续 2 轮无新因素、无新轴
4. **负空间**：列出"按常识该有、但我没找到"的因素 ← **最大的漏洞通常在这里**
5. **交互检查**：dominant/major 因素两两交互已查
6. **分层检查**：≥2 个关键分层是否反向

### 5. 维度总纲：14 个问题面（第三套覆盖）

前两套管的是"单个问题有多深"和"单个结果的因素类型"，都管不了"**这份调研该回答哪些面**"。投资人问市场，工程师问性能余量，采购问 TCO，法务问合规边界——少一面，报告在某一类读者眼里就是残缺的。

| # | 维度 | # | 维度 |
|---|---|---|---|
| D1 | 目标与决策场景 | D8 | 政策、法规与标准 |
| D2 | 定义、边界与口径 | D9 | 主体、激励与采购链条 |
| D3 | 性能与技术能力 | D10 | 时间、阶段与路线图 |
| D4 | 经济性（TCO） | D11 | 风险、失败模式与反例 |
| D5 | 市场与需求 | D12 | 证据质量与争议 |
| D6 | 竞争与同行 | D13 | 决策含义与替代方案 |
| D7 | 供应链、产能与交付 | D14 | 未解、负空间与下一步 |

每维都给：必答问题 / 需要什么材料 / **典型困难（分支从这里长出来）** / 最低证据 / 何时判 unknown。按对象类型激活必选维度，**未激活的必须写"为何不选"**。

**四轮查漏**（就是"重复去查有没有遗漏"）：R1 维度级 → R2 因素级 → R3 反例级（含退出者/失败案例专项）→ R4 负空间级。连续两轮零新增才叫饱和。

详见 [`references/dimension_outline.md`](ai-sq-universal/references/dimension_outline.md)。

### 6. 引用到句：证据的最小可核验单位

"有来源"不够。报告里最像证据、最不可靠的就是引用列表——**一段编造的引文读起来和真的一模一样，唯一区别是它定位不到**。

每条关键结论必须给：**定位**（页码/段落/条款/表格行/时间戳）+ **逐字原句** + 上下文 + 来源主体与发布日 + 追溯链。

四条硬规则：

1. **必须到句**：只给链接、只给报告名、"某公众号"一律不合格。
2. **二手按最弱一环定级**：公众号转述论文 = 按公众号定 C/D，且**必须尝试回溯一手**。
3. **公众号只作线索**；部门文件必须给 **文号 + 条款号 + 生效日**（并核对现行有效）。
4. **上下文防断章**：原文是否定句、在举例反驳、说的是他人观点——三种最容易被引成相反结论。

没有"句子"的来源：数据库用「库名+字段+期间+口径」定位；访谈/内部文件标 `unverified` 且不进关键结论；付费墙只引已读页。

详见 [`schemas/citation.json`](ai-sq-universal/schemas/citation.json) 与 [`prompts/citation_auditor.md`](ai-sq-universal/prompts/citation_auditor.md)。

## 运行流程（十三步）

```
INIT → BRIEF → AMBIGUITY_CHECK → SCOPE → COMPLEXITY → PLAN → RETRIEVE → EXTRACT
     → VERIFY → ANSWER_NODE → EXPAND_GAPS → FACTOR_SPACE → STOP_CHECK → NARRATE → REPORT
```

| 步 | 防的是什么 |
|---|---|
| INIT | 用错目标 |
| **BRIEF** | **精确但无用：没人能据此行动**（目的五问 + 五类相关方） |
| AMBIGUITY_CHECK | "几段"答错维度 |
| **SCOPE** | **只答被问到的，漏掉决定成败的变量**（需求外扩审计） |
| **COMPLEXITY** | 简单问题过度展开 / 复杂问题草草扫过 |
| PLAN | 空泛提问 |
| RETRIEVE | 拿百科当结论 |
| EXTRACT | 结论强度被悄悄放大（`quote` 必须逐字） |
| VERIFY | 类别套实例、相关当因果 |
| EXPAND_GAPS | 无限追问（一条缺口一条问题，≤5 条，去重） |
| **FACTOR_SPACE** | **只挖一条链就交卷** |
| **STOP_CHECK** | 把"没查完"伪装成"查清了" |
| **NARRATE** | 每节以"下表展示了…"开头，读完不知道结论是什么 |
| REPORT | 不可复核 |

## 证据等级（硬约束）

| 等级 | 含义 | 用途 |
|---|---|---|
| **A** | 权威库/标准/法规/指南/官方统计 + 高质量系统综述，多源一致 | 支撑关键结论 |
| **B** | 同行评议原始研究、权威机构报告 | 支撑结论 |
| **C** | 预印本、行业报告、单一研究、自动注释 | **仅作线索** |
| **D** | 百科、新闻、未验证网页 | **不作关键结论** |

领域包可**细化**，不可整体降级。无 ID 即降级并标 `id_missing`——编造 ID 比没有 ID 更糟。

## 停止规则

节点级九条（证据闭合 / 两轮无新信息 / 边际增益低 / 预算 / 只剩 C-D / 冲突不可消解 / 高风险需复核 / 超出检索范围 / 歧义未消解）。
全局：高优先级节点全关 **且** 六条覆盖判据满足，或预算耗尽并写明缺口。

**每次停止写 `stop_reason`。**

## 报告：§0 + 十四节（§1–§14），交付 Word

写作在 Markdown（模型好改），**交付是 Word**（读者要打开）。`scripts/build_docx.py` 从同一份 md 生成 docx：封面、目录、页眉页脚、斑马纹表格、可点击引用；另出 JSON 供机检。**禁止手工另存 Word**——那是文档与结论漂移的根源。v2.4 起报告以 **§0 目的与受益方**开篇，新增 §14 覆盖度与饱和声明——没有它，"全面"只是个形容词。
模板见 `templates/report.md`，填好的范例见 [`examples/01-bacteriology.md`](ai-sq-universal/examples/01-bacteriology.md)（含因素空间表与"覆盖不完整"的诚实声明）。

## 质量门禁

```bash
python ai-sq-universal/scripts/quality_gate.py report.md --json report.json --complexity 3 --risk high
```

按复杂度加码：L2 查因素与量级，L3 查交互/分层/`checked-none`，L4 查反馈与模型局限；另查十四节齐全、可追溯率、**引用定位可解析率**、**逐字原句列**、**模糊归因拦截**、**媒体不得评 A/B**、抽样核验记录、绝对化措辞、停止原因、免责声明、负空间。输出 PASS/FAIL 与退出码，可接 CI。

## 评测

13 个案例，覆盖科学、法律、金融、历史、技术、政策、商业、歧义对象、无答案问题、高风险问题，**两个 L3 多因素难例**（同政策两地相反、同菌株不同结局），以及**引用到句难例**（核实公众号二手数字并回溯一手）。每案带 `probes` / `must_show` / `must_not` / `expected_stop` / `complexity`；`must_not` 命中即判 0。

## 设计原则（十二条）

1. 领域无关内核 + 领域适配包——内核不写死任何领域术语
2. **先定复杂度档位，再决定展开深度**——防止八股与草率
3. **纵切求深，横切求全**——九层链 + 因素空间，缺一不可
4. 缺口驱动——只追信息缺口，不重复追问
5. 证据优先——关键结论必须有来源、原文句、ID、等级
6. 范围限定——全局/类别/实例/条件/时间/地域
7. 反例检查——"都/所有/一定/唯一/总是"出现即查反例
8. 层级校验——不得把载体当要素、产物当原因、类别属性套实例
9. 歧义先消解——先澄清或声明假设
10. **覆盖可验收**——六条判据，缺一条就说"覆盖不完整"
11. 高风险人工复核——医学/法律/金融/安全/政策/心理
12. 双输出——JSON + Markdown

## 失败模式与对策

| 失败模式 | 对策 |
|---|---|
| 无限追问 | 预算 + 去重键 + 边际增益停止 |
| **只挖一条链** | 复杂度定档 + 因素空间 + 轴枚举 |
| **因素清单无差别** | 强制 `magnitude` + `magnitude_basis` |
| **平均效应掩盖反向亚组** | 分层矩阵 + effect modification |
| **把相关当因果** | 混杂/中介/对撞检查 |
| **假全面** | §14 六条判据 + 负空间 |
| 编造 ID | 无 ID 降级，禁止推测 ID |
| 类别结论套实例 | `scope` + 反例 |
| 载体/要素/产物混淆 | `entity_levels` 校验 |
| "几段"答错 | `structure_semantics` 消歧 |
| 只查网页 | 源优先级 + 证据等级 |
| 冲突被抹平 | 保留争议，列冲突表 |
| 高风险误导 | 免责声明 + 人工复核 |

## 边界

- 不做实时行情/天气/比分。
- 不替代专业判断：医学/法律/金融输出是**信息整理**，不是诊疗/法律/投资意见。
- 不提供可用于实际危害操作的可执行细节（病原体增强、规避检测、武器化等）。
- **"未检索到" ≠ "不存在"**，报告会区分二者。
- 演绎问题（数学证明、代码推导）、审美判断、一手实验、内部数据：不适合，见 `references/domain_fit.md`。
