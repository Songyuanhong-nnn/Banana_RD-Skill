## 먼저 분명히: 이것이 아닌 것

v2.0은 "모든 영역에 적용된다"고 썼다. 그 문장은 이 Skill 자신의 5번째 원칙을 위반했다——**"모든"이라고 쓰면 반례를 찾아야 한다**. 반례는 바로 나왔고, 그래서 v2.1은 그 주장을 철회하고 정직한 목록으로 바꿨다:

| 적합도 | 영역 | 이유 |
|---|---|---|
| **강** | 과학 기제, 기술 선정, 역사 사료 | 결론이 1차 층에 착지하고 **반증 경로도 공개**된다(재현 실험, 소스코드＋실측, 사료 비판) |
| **중** | 법률, 금융·비즈니스, 정책 | 조문·공시·문서 검색에 강하지만 개별 사실, 내부 데이터, 반사실에 약하다 |
| **약** | 임상 판단, 사유 시스템 장애, 다주체 게임 | 결정 변수가 이번 개체·현재 국면의 사유 데이터여서 검색으로 닿지 않는다 |
| **부적용** | 수학적 증명, 심미적 판단, 실시간 판단, 비공개 데이터 | 연역 문제, 반증 가능한 claim 없음, 시간 예산 부족, 증거가 공개 영역 밖 |

전체 판정 기준, 각 영역의 "가장 오도되기 쉬운 지점"과 하향 경로는 [`references/domain_fit.md`](ai-sq-universal/references/domain_fit.md) 참조.

## 무엇을 보장하고, 무엇을 보장하지 않는가

**보장**: 결론은 추적 가능(ID ＋ 원문 문장 ＋ 등급). 범위는 검증된다(누구에게 성립하고 언제 성립하지 않는가). **요인은 열거된다**(사슬 하나 파고 제출하는 것이 아니다). 정지에는 이유가 있다("다 조사했다"와 "더는 못 한다"를 구분한다).

**보장하지 않음**: 실행 가능한 전문적 결정, 1차 데이터, 연역적 결론, 초 단위 답변.

## 핵심: 왜 세 가지 커버리지 기제가 필요한가

v2.0에는 9층 추적 사슬만 있었고, 그것은 **세로 절단**——하나의 대상을 질문 한 줄로 끝까지 파는 것이다. 그러나 실제 문제는 대개 "여러 요인이 함께 작용"한다. 세로 절단을 끝내도 사슬 세 개만 팠고 나머지 여섯 종류의 요인은 아예 떠올리지 못한 경우가 생긴다.

**깊이 ≠ 커버리지.** 게다가 세로 절단에는 더 은밀한 사각지대가 있다: "고객이 무엇을 물을지"를 모른다. 그래서 각 기제가 한 층씩 맡는다:

```
세로 절단: 9층 추적 사슬 ────────→ 깊게 (한 줄을 끝까지)
면: 14차원 총강(D1–D14)──────────→ 전부 (의사결정자가 묻는 면)
가로 절단: 요인 공간(9축＋크기)───→ 세밀하게 (요인 종류를 통째로 빠뜨리지 않기)
절단면: 층화 행렬 ───────────────→ 정확하게 (같은 요인이 국면에 따라 역전)
접합: 상호작용과 교란(15패턴)────→ 진실되게 (요인은 독립이 아니다)
수용: 커버리지 포화(6기준)───────→ 검증 가능 ("전면"이 형용사가 아니게)
인용: 문장 단위 인용(위치＋원문)──→ 확인 가능 (모든 결론을 30초에 재확인)
```

### 1. 복잡도 티어 L1–L4: 먼저 등급을 정하고, 그다음 전개량을 정한다

| 티어 | 구조적 기준 | 필수 점검 |
|---|---|---|
| **L1 단일 사슬** | 단일 주원인→주결과, 그리고 층화·상호작용 점검에서 부호 반전 없음 | 9층 사슬＋반례, 요인 공간은 만들지 않음 |
| **L2 다요인** | 상대적으로 독립적인 요인 ≥3, 점검에서 부호 반전 없음 | 요인 공간＋크기＋공선성·교란 초검 |
| **L3 상호작용·이질** | 층화 후 부호 반전, 결합 효과 비가산, 임계값·비선형, 사례 간 기제 상이 | L2＋상호작용 행렬＋층화 행렬 |
| **L4 동적 시스템** | 인과 그래프에 양방향 변, 양방향 시간 증거, 알려진 지연, 레짐 시프트 | L3＋인과 그래프＋지연＋시나리오 분석＋모델 한계 3필드 |

다섯 가지 하드 규칙 중 가장 중요한 둘:

- **티어는 요인 수와 직교한다**: 요인이 많아도 모두 선형이면 L2, 요인이 적어도 강한 피드백이면 L4. "요인이 많다"를 "복잡하다"로 착각하지 말 것.
- **티어 ≠ 완성도**: 티어는 "어떤 점검이 필수인가"를 정하고, 예산은 "이번에 몇 개를 끝내는가"를 정한다. 예산이 부족해도 **티어를 낮추지 않는다**. 미완 항목은 `unchecked`로 표시한다——티어를 낮추면 "조사하지 않음"이 조용히 "조사할 필요 없음"으로 변한다.

자기기만에 대한 특효약 하나 더: **"부호 반전을 찾지 못했다"는 "부호 반전이 없다"가 아니다**. 층화·상호작용 점검을 하지 않았다면 L1/L2로 판정할 자격이 없다. 한 단계 높은 티어로 다루고 `gaps`에 흔적을 남긴다.

### 2. 요인 공간: 축별로 열거하고, 기억에 의존하지 않는다

9개 축을 기계적으로 한 번 훑는다. 각 축은 요인을 가지거나 "비어 있음, 이유"를 쓴다. 공백과 "확인 후 없음"은 다른 것이다.

| 축 | 가장 잘 빠지는 것 |
|---|---|
| 시간 | 횡단면 데이터를 인과로 취급, 지연이 보이지 않음 |
| 공간·계층 | 생태학적 오류(집단 결론을 개인에 적용) |
| 주체 | 객관적 요인만 세고 "누가 결정하는가"를 빠뜨림 |
| 물질·자원 | 자원 제약을 "다른 조건 불변"으로 취급 |
| 규칙·제도 | 제도 변화가 효과를 역전시키는 것을 무시 |
| 정보·인지 | 주체가 전지적·합리적이라고 가정 |
| 기술·도구 | 기술 세대 차이를 무시 |
| 환경·외부 충격 | 일회성 충격을 구조적 원인으로 씀 |
| 피드백·동역학 | 정적 틀로는 동역학이 보이지 않음 |

모든 요인은 `role`(필요/촉진/임계/조절/교란), `direction`, **`magnitude`**, `magnitude_basis`, `proxy`, `how_to_test`를 반드시 갖는다.

**크기는 하드 요건**: `dominant` / `major` / `minor` / `unknown`(unknown은 이유 필수). "위 요인은 모두 중요하므로 종합적으로 고려해야 한다"는 금지——그 문장의 정보량은 0이다.

### 3. 상호작용과 교란: 능동적으로 비교해야 할 15개 패턴

[`references/complexity_patterns.md`](ai-sq-universal/references/complexity_patterns.md) 참조: 교란, 매개, 효과 수정, 상호작용, 콜라이더, Simpson, 생태학적 오류, 임계값, 피드백, 지연, 경로 의존, 등가 경로, 대리 오차, 선택 편향, 상전이. 각 항목에 "식별 방법 / 반드시 물을 것 / 검색 단서 / 흔한 오판" 포함.

출력에는 반드시 `checked-none`이 포함되어야 한다——**그렇지 않으면 독자는 "조사했으나 없음"과 "아예 조사하지 않음"을 구분할 수 없다**.

### 4. 커버리지 포화: "전면"을 검증 가능하게 만들기

보고서 §14의 6가지 기준. 하나라도 빠지면 "체계적으로 커버했다"고 말할 수 없다:

1. **축 커버리지**: 9축을 지나갔고, 빈 축에는 이유
2. **크기 커버리지**: 모든 요인에 크기, unknown에는 원인
3. **포화**: 연속 2라운드에서 새 요인·새 축 없음
4. **네거티브 스페이스**: "상식적으로 있어야 하는데 찾지 못한" 요인 나열 ← **가장 큰 구멍은 대개 여기**
5. **상호작용 점검**: dominant/major 요인의 모든 쌍 확인 완료
6. **층화 점검**: 핵심 층화 ≥2가 역전하는지

### 5. 차원 총강: 14개 질문 면(세 번째 커버리지)

앞의 둘은 "단일 질문이 얼마나 깊은가"와 "단일 결과가 어떤 요인 유형을 갖는가"를 다룬다. 둘 다 "**이 조사가 어떤 면에 답해야 하는가**"는 다루지 못한다. 투자자는 시장을, 엔지니어는 성능 여유를, 구매는 TCO를, 법무는 컴플라이언스 경계를 묻는다——한 면이 빠지면 그 부류의 독자에게 보고서는 불완전하다.

| # | 차원 | # | 차원 |
|---|---|---|---|
| D1 | 목표와 의사결정 맥락 | D8 | 정책·법규·표준 |
| D2 | 정의·경계·집계 기준 | D9 | 주체·인센티브·조달 사슬 |
| D3 | 성능과 기술 역량 | D10 | 시간·단계·로드맵 |
| D4 | 경제성(TCO) | D11 | 리스크·실패 모드·반례 |
| D5 | 시장과 수요 | D12 | 증거 품질과 논쟁 |
| D6 | 경쟁과 동종 | D13 | 의사결정 함의와 대안 |
| D7 | 공급망·생산능력·납기 | D14 | 미해결·네거티브 스페이스·다음 단계 |

각 차원에: 필수 질문 / 필요한 자료 / **전형적 어려움(여기서 분기가 자란다)** / 최소 증거 / 언제 unknown으로 판정하는가. 대상 유형별로 필수 차원을 활성화하고, **활성화하지 않은 차원은 "왜 선택하지 않았는가"를 쓴다**.

**4라운드 누락 탐색**("누락이 없는지 반복 확인"): R1 차원 → R2 요인 → R3 반례(퇴출자·실패 사례 전용 포함) → R4 네거티브 스페이스. 연속 두 라운드 신규 0이어야 포화.

자세한 내용은 [`references/dimension_outline.md`](ai-sq-universal/references/dimension_outline.md).

### 6. 문장 단위 인용: 증거의 최소 검증 단위

"출처가 있다"로는 부족하다. 보고서에서 가장 증거 같으면서 가장 신뢰할 수 없는 것이 인용 목록이다——**조작된 인용문은 진짜와 똑같이 읽힌다. 유일한 차이는 위치를 특정할 수 없다는 것뿐**이다.

모든 핵심 결론에는 **위치**(페이지/문단/조항/표 행/타임스탬프) ＋ **축자 원문** ＋ 맥락 ＋ 출처 주체와 발표일 ＋ 소급 사슬을 준다.

네 가지 하드 규칙:

1. **문장까지 도달할 것**: 링크만, 보고서 이름만, "모 신규 계정"은 일률 부적격.
2. **2차 자료는 가장 약한 고리로 등급화**: 위챗이 논문을 전달한 것 = 위챗으로 C/D, 그리고 **1차로 소급 시도 필수**.
3. **위챗은 단서일 뿐**; 부처 문서는 **문서번호＋조항번호＋시행일**을 반드시 제시(현행 유효성 확인 포함).
4. **맥락으로 단장 방지**: 원문이 부정문, 반박을 위한 예시, 타인 견해 전달——이 셋이 인용을 반대 결론으로 바꾸기 가장 쉽다.

"문장"이 없는 출처: 데이터베이스는 「DB명＋필드＋기간＋기준」으로 위치 지정. 인터뷰/내부 문서는 `unverified`로 표시하고 핵심 결론에 넣지 않는다. 페이월은 실제로 읽은 페이지만 인용.

자세한 내용은 [`schemas/citation.json`](ai-sq-universal/schemas/citation.json)과 [`prompts/citation_auditor.md`](ai-sq-universal/prompts/citation_auditor.md).

## 실행 흐름(13단계)

```
INIT → BRIEF → AMBIGUITY_CHECK → SCOPE → COMPLEXITY → PLAN → RETRIEVE → EXTRACT
     → VERIFY → ANSWER_NODE → EXPAND_GAPS → FACTOR_SPACE → STOP_CHECK → NARRATE → REPORT
```

| 단계 | 무엇을 막는가 |
|---|---|
| INIT | 목표 오용 |
| **BRIEF** | **정확하지만 무용: 아무도 행동할 수 없음**(목적 5문＋5류 이해관계자) |
| AMBIGUITY_CHECK | "몇 단락"을 잘못된 차원으로 답함 |
| **SCOPE** | **물어본 것만 답하고 성패를 가르는 변수를 놓침**(요구 확장 감사) |
| **COMPLEXITY** | 단순한 문제의 과잉 전개 / 복잡한 문제의 조잡한 처리 |
| PLAN | 공허한 질문 |
| RETRIEVE | 백과사전을 결론으로 취급 |
| EXTRACT | 결론 강도가 조용히 부풀려짐(`quote`는 축자 필수) |
| VERIFY | 범주를 개별 사례에 적용, 상관을 인과로 |
| EXPAND_GAPS | 무한 추적(갭 하나에 질문 하나, ≤5, 중복 제거) |
| **FACTOR_SPACE** | **사슬 하나 파고 제출** |
| **STOP_CHECK** | "다 못 봄"을 "다 봄"으로 위장 |
| **NARRATE** | 각 절이 "아래 표는…"으로 시작해 결론을 알 수 없음 |
| REPORT | 재확인 불가 |

## 증거 등급(하드 제약)

| 등급 | 의미 | 용도 |
|---|---|---|
| **A** | 권위 DB/표준/법규/가이드라인/공식 통계 ＋ 고품질 체계적 문헌고찰, 다출처 일치 | 핵심 결론 지지 |
| **B** | 동료심사 1차 연구, 권위 기관 보고서 | 결론 지지 |
| **C** | 프리프린트, 업계 보고서, 단일 연구, 자동 주석 | **단서로만** |
| **D** | 백과사전, 뉴스, 미검증 웹페이지 | **핵심 결론에 사용 불가** |

영역 팩은 등급을 **세분화**할 수 있지만 전체를 하향할 수는 없다. ID가 없으면 하향하고 `id_missing`을 표시——ID 조작은 ID 없음보다 나쁘다.

## 정지 규칙

노드 수준 9조건(증거 폐합 / 두 라운드 새 정보 없음 / 한계 이득 낮음 / 예산 / C–D만 남음 / 충돌 해소 불가 / 고위험 재확인 필요 / 검색 범위 초과 / 모호성 미해소).
전체: 고우선 노드가 모두 닫히고 **그리고** 6개 커버리지 기준을 충족, 또는 예산 소진과 갭 명시.

**정지할 때마다 `stop_reason`을 쓴다.**

## 보고서: §0 ＋14절(§1–§14), Word로 납품

집필은 Markdown(모델이 고치기 쉬움), **납품은 Word**(독자가 열어야 함). `scripts/build_docx.py`가 같은 md에서 docx를 생성: 표지, 목차, 머리말·꼬리말, 얼룩무늬 표, 클릭 가능한 인용. 기계 검사용 JSON도 출력. **수작업으로 Word에 다른 이름 저장 금지**——그것이 문서와 결론이 어긋나는 근원이다. v2.4부터 보고서는 **§0 목적과 수혜자**로 시작하고 §14 커버리지·포화 선언을 추가——이것이 없으면 "전면"은 그저 형용사다.

템플릿은 `templates/report.md`, 작성 예시는 [`examples/01-bacteriology.md`](ai-sq-universal/examples/01-bacteriology.md)(요인 공간 표와 "커버리지 불완전"의 정직한 선언 포함).

## 품질 게이트

```bash
python ai-sq-universal/scripts/quality_gate.py report.md --json report.json --complexity 3 --risk high
```

복잡도에 따라 강화: L2는 요인과 크기, L3는 상호작용·층화·`checked-none`, L4는 피드백과 모델 한계를 점검. 또한 14절 완비, 추적 가능률, **인용 위치 해석 가능률**, **축자 원문 열**, **모호 귀속 차단**, **미디어를 A/B로 평가 금지**, 표본 검증 기록, 절대적 표현, 정지 이유, 면책 조항, 네거티브 스페이스를 점검. PASS/FAIL과 종료 코드를 출력하며 CI에 연결 가능.

## 평가

13개 사례. 과학, 법률, 금융, 역사, 기술, 정책, 비즈니스, 모호한 대상, 답 없는 질문, 고위험 질문을 포괄하며, **두 개의 어려운 L3 다요인 사례**(같은 정책에 두 지역이 반대, 같은 균주에 결과가 다름)와 **문장 단위 인용 난제**(위챗 2차 숫자를 검증하고 1차로 소급)를 포함. 각 사례에 `probes` / `must_show` / `must_not` / `expected_stop` / `complexity`를 붙이고, `must_not` 적중 시 0점.

---

## 설계 원칙(12)

1. 영역 무관 커널 ＋ 영역 어댑터 팩——커널에 어떤 영역 용어도 하드코딩하지 않음
2. **먼저 복잡도 티어를 정하고, 그다음 깊이를 정한다**——상투성과 조잡함 방지
3. **세로로 깊이, 가로로 전면**——9층 사슬＋요인 공간, 둘 다 필수
4. 갭 주도——정보 갭만 추적하고 같은 질문을 반복하지 않음
5. 증거 우선——핵심 결론에는 출처·원문·ID·등급 필요
6. 범위 한정——전체/범주/개별/조건/시간/지역
7. 반례 점검——"모두/모든/반드시/유일/항상"이 나오면 반례를 찾음
8. 계층 검증——담체를 요소로, 산물을 원인으로, 범주 속성을 개별 사례에 적용하지 않음
9. 모호성 선해소——먼저 명확히 하거나 가정을 선언
10. **커버리지 검증 가능**——6기준, 하나 빠지면 "커버리지 불완전"이라고 말함
11. 고위험은 사람이 재확인——의학/법률/금융/보안/정책/심리
12. 이중 출력——JSON ＋ Markdown

## 경계

- 실시간 시세/날씨/점수는 다루지 않는다.
- 전문적 판단을 대체하지 않는다: 의학/법률/금융 출력은 **정보 정리**이며 진료·법률·투자 의견이 아니다.
- 실제 위해에 쓸 수 있는 실행 가능한 세부(병원체 강화, 검출 회피, 무기화 등)는 제공하지 않는다.
- **"검색해서 없음" ≠ "존재하지 않음"**——보고서는 둘을 구분한다.
- 연역 문제(수학적 증명, 코드 유도), 심미적 판단, 1차 실험, 내부 데이터: 부적합. `references/domain_fit.md` 참조.
