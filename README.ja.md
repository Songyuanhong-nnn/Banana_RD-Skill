## まず明確に：これは何ではないか

v2.0 は「あらゆる領域に適用できる」と書いていた。その一文は、この Skill 自身の第 5 原則に違反していた——**「すべて」と書いたら反例を探さなければならない**。反例はすぐ見つかったので、v2.1 はその主張を撤回し、正直な一覧表に置き換えた：

| 適合度 | 領域 | 理由 |
|---|---|---|
| **強** | 科学機構、技術選定、歴史史料 | 結論が一次層に着地し、**反証経路も公開されている**（再現実験、ソースコード＋実測、史料批判） |
| **中** | 法律、金融・ビジネス、政策 | 条文・開示・文書検索に強いが、個別事実・内部データ・反事実に弱い |
| **弱** | 臨床判断、私有システムの障害、多主体ゲーム | 決定変数が本次の個体・現在の局面の私有データであり、検索では届かない |
| **不適用** | 数学的証明、審美判断、リアルタイム判断、非公開データ | 演繹問題、反証可能な claim がない、時間予算が許さない、証拠が公開領域にない |

完全な判定基準、各領域の「最も誤導されやすい点」と劣化経路は [`references/domain_fit.md`](ai-sq-universal/references/domain_fit.md) を参照。

## 何を保証し、何を保証しないか

**保証する**：結論は追跡可能（ID ＋ 原文文 ＋ 等級）。範囲は検証される（誰に成立し、いつ成立しないか）。**要因は列挙される**（一本の鎖を掘って提出、ではない）。停止には理由がある（「調べ終えた」と「これ以上調べられない」を区別する）。

**保証しない**：実行可能な専門的決定、一次データ、演繹的結論、秒単位の回答。

## 核心：なぜ三つのカバレッジ機構が必要か

v2.0 には九層の追及鎖しかなく、それは**縦切り**——一つの対象を一連の問いに沿って底まで掘るものだった。しかし現実の問いはたいてい「多くの要因が同時に作用する」ものだ。縦切りを走り終えても三本の鎖しか掘れておらず、残り六種類の要因はそもそも思いつかれていない、ということが起きる。

**深さ ≠ カバレッジ。** さらに縦切りには隠れた盲点がある：「依頼者が何を聞くか」を知らないのだ。そこで各機構が一層ずつ担う：

```
縦切り：九層追及鎖 ────────────→ 深（一本の線を底まで）
面：14 次元総綱（D1–D14）──────→ 全（意思決定者が問う面）
横切り：要因空間（9 軸＋量級）──→ 細（要因の種類ごと漏らさない）
切断面：層別マトリクス ────────→ 正確（同一要因が文脈で逆転する）
接続：交互作用と交絡（15 パターン）→ 真（要因は独立でない）
受入：カバレッジ飽和（6 基準）──→ 検証可能（「全面」が形容詞でなくなる）
引用：文単位引用（位置＋原文）──→ 照合可能（各結論を 30 秒で再確認）
```

### 1. 複雑度ティア L1–L4：まず段階を決め、それから展開量を決める

| ティア | 構造的基準 | 必須チェック |
|---|---|---|
| **L1 単一鎖** | 単一の主因→主結果、かつ層別・交互作用チェックで符号反転なし | 九層鎖＋反例、要因空間は作らない |
| **L2 多要因** | 比較的独立した要因が 3 つ以上、かつチェックで符号反転なし | 要因空間＋量級＋共線性・交絡の初査 |
| **L3 交互・異質** | 層別後に符号反転、結合効果が非加算、閾値・非線形、事例間で機構が異なる | L2＋交互作用マトリクス＋層別マトリクス |
| **L4 動的システム** | 因果グラフに双方向辺、双方向の時間証拠、既知の遅延、レジームシフト | L3＋因果グラフ＋遅延＋シナリオ分析＋モデル限界の三フィールド |

五つのハードルールのうち、最も重要な二つ：

- **ティアは要因数と直交する**：要因が多くてもすべて線形なら L2。要因が少なくても強いフィードバックがあれば L4。「要因が多い」を「複雑」と取り違えない。
- **ティア ≠ 完成度**：ティアは「どのチェックが必須か」を決め、予算は「今回いくつ終えられるか」を決める。予算不足でも**ティアを下げない**。未完了項目は `unchecked` と記す——ティアを下げると「調べていない」が静かに「調べる必要がない」に変わる。

もう一つ、自己欺瞞への特効薬：**「符号反転が見つからなかった」は「符号反転がない」ではない**。層別・交互作用チェックをしていないなら L1/L2 と判定する資格はない。一段上のティアとして扱い、`gaps` に痕跡を残す。

### 2. 要因空間：軸ごとに列挙し、記憶に頼らない

九軸を機械的に一度通す。各軸は要因を持つか、「空、理由」を書くかのどちらか。空白と「確認した上での不在」は別物だ。

| 軸 | 最も漏れやすいもの |
|---|---|
| 時間 | 横断データを因果とみなす、遅延が見えない |
| 空間・階層 | 生態学的誤謬（集団の結論を個体に当てはめる） |
| 主体 | 客観的要因だけを数え、「誰が決めるか」を落とす |
| 物質・資源 | 資源制約を「他の条件は一定」として扱う |
| 規則・制度 | 制度変化による効果の逆転を無視する |
| 情報・認知 | 主体が全知で合理的だと仮定する |
| 技術・道具 | 技術の世代差を無視する |
| 環境・外部衝撃 | 一度きりの衝撃を構造的原因として書く |
| フィードバック・動態 | 静的枠組みでは動態が見えない |

各要因は `role`（必要／促進／閾値／調整／交絡）、`direction`、**`magnitude`**、`magnitude_basis`、`proxy`、`how_to_test` を必ず持つ。

**量級は必須**：`dominant` / `major` / `minor` / `unknown`（unknown は理由必須）。「以上の要因はすべて重要であり、総合的に考慮する必要がある」は禁止——その文の情報量はゼロだ。

### 3. 交互作用と交絡：能動的に比較すべき 15 パターン

[`references/complexity_patterns.md`](ai-sq-universal/references/complexity_patterns.md) を参照：交絡、媒介、効果修飾、交互作用、コライダー、Simpson、生態学的誤謬、閾値、フィードバック、遅延、経路依存、等価経路、代理誤差、選択バイアス、相転移。各項目に「見分け方／必ず問うこと／検索の手がかり／よくある誤判定」を含む。

出力には `checked-none` を必ず含める——**そうでなければ読者は「調べて無かった」と「そもそも調べていない」を区別できない**。

### 4. カバレッジ飽和：「全面」を検証可能にする

レポート §14 の六基準。一つでも欠ければ「体系的にカバーした」と言ってはならない：

1. **軸カバレッジ**：9 軸を通し、空の軸には理由
2. **量級カバレッジ**：各要因に量級、unknown には原因
3. **飽和**：連続 2 ラウンドで新要因・新軸なし
4. **ネガティブスペース**：「常識的にあるはずだが、見つからなかった」要因の列挙 ← **最大の穴はたいていここ**
5. **交互作用チェック**：dominant/major 要因の全ペアを確認済み
6. **層別チェック**：重要な層別 ≥2 が逆転するか

### 5. 次元総綱：14 の問いの面（第三のカバレッジ）

最初の二つは「単一の問いがどれだけ深いか」と「単一の結果がどんな要因類型を持つか」を扱う。どちらも「**この調査はどの面に答えるべきか**」は扱えない。投資家は市場を、技術者は性能余裕を、購買は TCO を、法務はコンプライアンス境界を問う——一面欠ければ、その種の読者にとってレポートは不完全になる。

| # | 次元 | # | 次元 |
|---|---|---|---|
| D1 | 目的と意思決定の文脈 | D8 | 政策・法規・標準 |
| D2 | 定義・境界・計量口径 | D9 | 主体・インセンティブ・調達連鎖 |
| D3 | 性能と技術的能力 | D10 | 時間・段階・ロードマップ |
| D4 | 経済性（TCO） | D11 | リスク・失敗モード・反例 |
| D5 | 市場と需要 | D12 | 証拠の質と論争 |
| D6 | 競争と同業 | D13 | 意思決定上の含意と代替案 |
| D7 | サプライチェーン・生産能力・納品 | D14 | 未解決・ネガティブスペース・次の一手 |

各次元に：必答の問い／必要な資料／**典型的困難（ここから分岐が生える）**／最低証拠／いつ unknown と判定するか。対象類型ごとに必須次元を起動し、**起動しない次元は「なぜ選ばないか」を書く**。

**四ラウンドの漏れ探し**（「漏れがないか繰り返し確認する」こと）：R1 次元レベル → R2 要因レベル → R3 反例レベル（退出者・失敗事例の専項を含む）→ R4 ネガティブスペースレベル。連続二ラウンドで新規ゼロなら飽和。

詳細は [`references/dimension_outline.md`](ai-sq-universal/references/dimension_outline.md)。

### 6. 文単位引用：証拠の最小検証単位

「出典がある」では足りない。レポートの中で最も証拠らしく、最も信頼できないのが参考文献一覧だ——**捏造された引用文は本物とまったく同じように読める。唯一の違いは位置を特定できないことだけ**。

各重要結論には必ず：**位置**（ページ／段落／条項／表の行／タイムスタンプ）＋**逐語原文**＋文脈＋出典主体と公開日＋遡及連鎖を与える。

四つのハードルール：

1. **文まで届くこと**：リンクだけ、レポート名だけ、「某 WeChat アカウント」は一律不合格。
2. **二次資料は最も弱い環で等級付け**：WeChat が論文を伝聞したもの＝WeChat として C/D、かつ**一次資料への遡及を必ず試みる**。
3. **WeChat は手がかりに過ぎない**；部門文書は**文書番号＋条項番号＋施行日**を必ず示す（現行有効性も確認）。
4. **文脈で断章を防ぐ**：原文が否定文である、反駁のための例示である、他者の見解を述べている——この三つが最も引用を逆の結論に変えやすい。

「文」を持たない出典：データベースは「DB 名＋フィールド＋期間＋口径」で位置づける。インタビュー／内部文書は `unverified` と記し重要結論に入れない。ペイウォールは実際に読んだページのみ引用する。

詳細は [`schemas/citation.json`](ai-sq-universal/schemas/citation.json) と [`prompts/citation_auditor.md`](ai-sq-universal/prompts/citation_auditor.md)。

## 実行フロー（十三ステップ）

```
INIT → BRIEF → AMBIGUITY_CHECK → SCOPE → COMPLEXITY → PLAN → RETRIEVE → EXTRACT
     → VERIFY → ANSWER_NODE → EXPAND_GAPS → FACTOR_SPACE → STOP_CHECK → NARRATE → REPORT
```

| ステップ | 何を防ぐか |
|---|---|
| INIT | 目標の取り違え |
| **BRIEF** | **正確だが無用：誰も行動できない**（目的の五問＋五類の関係者） |
| AMBIGUITY_CHECK | 「何段落」を誤った次元で答える |
| **SCOPE** | **聞かれたことだけに答え、成否を決める変数を落とす**（要求拡張監査） |
| **COMPLEXITY** | 単純な問いの過剰展開／複雑な問いの粗い処理 |
| PLAN | 空疎な問い |
| RETRIEVE | 百科事典を結論として扱う |
| EXTRACT | 結論の強度が静かに膨らむ（`quote` は逐語必須） |
| VERIFY | カテゴリを個別事例に当てる、相関を因果とみなす |
| EXPAND_GAPS | 無限の追及（ギャップ一つに問い一つ、≤5、重複排除） |
| **FACTOR_SPACE** | **一本の鎖を掘っただけで提出** |
| **STOP_CHECK** | 「調べ終えていない」を「調べ終えた」に偽装 |
| **NARRATE** | 各節が「以下の表は…」で始まり、結論が分からない |
| REPORT | 再確認できない |

## 証拠等級（ハード制約）

| 等級 | 意味 | 用途 |
|---|---|---|
| **A** | 権威 DB／標準／法規／ガイドライン／公式統計＋高品質な系統的レビュー、複数ソース一致 | 重要結論を支える |
| **B** | 査読済み一次研究、権威機関レポート | 結論を支える |
| **C** | プレプリント、業界レポート、単一研究、自動注釈 | **手がかりのみ** |
| **D** | 百科事典、ニュース、未検証のウェブページ | **重要結論には使わない** |

領域パックは等級を**細分化**できるが、全体を引き下げることはできない。ID がなければ格下げし `id_missing` を付す——ID の捏造は ID なしより悪い。

## 停止規則

ノードレベル九条件（証拠閉合／二ラウンド新情報なし／限界利得が低い／予算／C–D のみ／衝突が解消不能／高リスクで要再確認／検索範囲外／曖昧性未解消）。
全体：高優先ノードがすべて閉じ、**かつ**六つのカバレッジ基準を満たす。または予算枯渇でギャップを明記。

**停止のたびに `stop_reason` を書く。**

## レポート：§0 ＋十四節（§1–§14）、Word で納品

執筆は Markdown（モデルが直しやすい）、**納品は Word**（読者が開く）。`scripts/build_docx.py` が同じ md から docx を生成：表紙、目次、ヘッダ・フッタ、縞模様の表、クリック可能な引用。機械検査用の JSON も出力。**手作業で Word に名前を付けて保存することは禁止**——それが文書と結論の乖離の根源だ。v2.4 からレポートは **§0 目的と受益者**で始まり、§14 カバレッジと飽和の宣言を追加——これがないと「全面」はただの形容詞になる。

テンプレートは `templates/report.md`、記入例は [`examples/01-bacteriology.md`](ai-sq-universal/examples/01-bacteriology.md)（要因空間表と「カバレッジ不完全」の正直な宣言を含む）。

## 品質ゲート

```bash
python ai-sq-universal/scripts/quality_gate.py report.md --json report.json --complexity 3 --risk high
```

複雑度に応じて強化：L2 は要因と量級、L3 は交互作用・層別・`checked-none`、L4 はフィードバックとモデル限界を検査。さらに十四節の完備、追跡可能率、**引用位置の解析可能率**、**逐語原文列**、**曖昧帰属の阻止**、**メディアを A/B と評価しないこと**、抽出検証記録、絶対的表現、停止理由、免責事項、ネガティブスペースを検査。PASS/FAIL と終了コードを出力し、CI に接続可能。

## 評価

13 ケース。科学、法律、金融、歴史、技術、政策、ビジネス、曖昧な対象、答えのない問い、高リスクの問いをカバーし、**二つの難しい L3 多要因ケース**（同一政策で二地域が逆、同一菌株で転帰が異なる）と**文単位引用の難ケース**（WeChat の二次数字を検証し一次へ遡る）を含む。各ケースに `probes` / `must_show` / `must_not` / `expected_stop` / `complexity` を付し、`must_not` に該当すれば 0 点。

## 設計原則（十二）

1. 領域非依存の核＋領域アダプタパック——核に領域用語を書き込まない
2. **先に複雑度ティアを決め、それから深さを決める**——八股と粗雑の防止
3. **縦切りで深さ、横切りで全面**——九層鎖＋要因空間、どちらも必須
4. ギャップ駆動——情報ギャップのみを追い、同じ問いを繰り返さない
5. 証拠優先——重要結論には出典・原文・ID・等級が必要
6. 範囲限定——全体／カテゴリ／個別／条件／時間／地域
7. 反例検査——「すべて／必ず／唯一／常に」が出たら反例を探す
8. 階層検証——担体を要素と、産物を原因と、カテゴリ属性を個別事例と取り違えない
9. 曖昧性の先払い——まず明確化するか仮定を宣言する
10. **カバレッジ検証可能**——六基準、一つ欠ければ「カバレッジ不完全」と言う
11. 高リスクは人による再確認——医学／法律／金融／安全／政策／心理
12. 二重出力——JSON ＋ Markdown

## 失敗モードと対策

| 失敗モード | 対策 |
|---|---|
| 無限の追及 | 予算＋重複排除キー＋限界利得での停止 |
| **一本の鎖だけ掘る** | 複雑度ティア＋要因空間＋軸列挙 |
| **要因リストに差がない** | `magnitude` ＋ `magnitude_basis` の強制 |
| **平均効果が逆の亜群を覆い隠す** | 層別マトリクス＋効果修飾 |
| **相関を因果とみなす** | 交絡／媒介／コライダーの検査 |
| **偽の全面性** | §14 六基準＋ネガティブスペース |
| ID の捏造 | ID なしは格下げ、ID の推測は禁止 |
| カテゴリ結論を個別事例に当てる | `scope` ＋反例 |
| 担体／要素／産物の混同 | `entity_levels` 検証 |
| 「何段落」の誤答 | `structure_semantics` による曖昧性解消 |
| ウェブページだけを調べる | ソース優先度＋証拠等級 |
| 衝突を均す | 論争を保持し、衝突表を載せる |
| 高リスクの誤導 | 免責事項＋人による再確認 |

## 境界

- リアルタイムの相場／天気／スコアは扱わない。
- 専門的判断を代替しない：医学／法律／金融の出力は**情報整理**であり、診療・法律・投資の意見ではない。
- 実際の危害に使える実行可能な詳細（病原体の強化、検出回避、兵器化など）は提供しない。
- **「検索して見つからない」≠「存在しない」**——レポートは両者を区別する。
- 演繹問題（数学的証明、コード導出）、審美判断、一次実験、内部データ：不適。`references/domain_fit.md` を参照。
