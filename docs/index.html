求根问底，
而不是看起来查过了

一个把「全面」变成可验收的调研内核。14 维问题面保证该问的都问到， 九层追问链保证每条都挖到底，因素空间保证整类因素不被漏掉， 引用到句保证每条结论 30 秒可复核。

快速开始 读主规范 SKILL.md
一句话内核

求根问底 = 问题树 × 证据链 × 缺口递归 × 因素空间 × 范围与反例 × 层级校验 × 覆盖饱和 × 停止控制 × 结构化报告。

三路并行，缺一不可：纵切保证问得深，面覆盖保证该问的都问到，横切保证整类因素不漏。三条线在「覆盖饱和」处收口，才允许出报告。
⚖️先说清楚：它不是什么

v2.0 曾说「适用于所有领域」
那句话违反了它自己的第 5 条原则

出现「所有」就必须查反例。反例是现成的，所以 v2.1 把它撤了，换成一张诚实的账。 这张表本身就是这个 Skill 的示范：能证伪，才敢下结论。

强 结论落在一手层
  • 科学机制
  • 技术选型
  • 历史史料

强在条文 / 披露 / 文件检索；弱在个案事实、内部数据、反事实。

演绎问题、无可证伪 claim、时间预算不允许、证据不在公开域。
🧩为什么需要三套覆盖机制

层数深 ≠ 覆盖面全

只有九层追问链是纵切——把一个对象顺着一串问题挖到底。但真实问题通常是「很多因素共同作用」， 纵切跑完可能只挖了三条链，另外六类因素根本没被想到过。而且纵切还有个更隐蔽的盲区： 它不知道「客户会问什么」。所以七套机制各管一层。

📐先定档，再决定展开多少

复杂度分级 L1–L4

防止两种失败同时发生：简单问题被过度展开成八股， 复杂问题被草草扫过。档位决定「必须做哪些检查」，预算决定「这次做完几项」—— 预算不足不降档，把未完成项标 unchecked。

L1
单链
九层链 + 反例
不建因素空间
L2
多因素
+ 因素空间 + 量级
共线 / 混杂初查
L3
交互 / 异质
+ 交互矩阵
+ 分层矩阵
L4
动态系统
+ 因果图 + 时滞
+ 情景 + 模型局限

档位与因素数量正交：因素多但全线性 = L2；因素少但有强反馈 = L4。 档位 ≠ 完成度：预算不足不降档，把未完成项标 unchecked—— 降档会让「没查」悄悄变成「不需要查」。

🔍证据的最小可核验单位

「有来源」不够，要引用到那一句

报告里最像证据、最不可靠的就是引用列表。四条硬规则： 必须到句、二手按最弱一环定级、 公众号只作线索、上下文防断章。

不合格

据某公众号报道，该菌株致病率约为 30%。

无定位 · 无原句 · 无发布日 · 二手转述未回溯
合格

「在 47 株分离株中，14 株（29.8%）检出 stx2 基因。」

E-0142 · 第 3 页 · 表 2 第 4 行
来源：J. Clin. Microbiol. 2019;57(4) · 2019-04-01
A
权威库 / 标准 / 法规 / 官方统计 + 高质量系统综述，多源一致
B
同行评议原始研究、权威机构报告
C
预印本、行业报告、单一研究、自动注释 — 仅作线索
D
百科、新闻、未验证网页 — 不作关键结论
⚙️一次运行

十三步，每一步防一种具体的偷懒

流程不是装饰。每一步都对应一个真实发生过的失败模式—— 加粗的是 v2.4 新增的三道闸：BRIEF（为谁而答）、SCOPE（用户列举是下限不是上限）、NARRATE（每节首句必须是判断）。

十五个检查点归为五个阶段。每个节点都对应一个真实发生过的失败模式——不是流程装饰。

BRIEF · 目的五问

决定 / 时点 / 答错代价 / 成功标准 / 明确不做什么 + 五类相关方（决策者 / 付费者 / 使用者 / 被影响者 / 守门人）。缺哪类必须写「为何不适用」。

SCOPE · 外扩审计

必要遗漏 / 目的错位（问的是手段、真实要的是结果）/ 成败变量（预算、人员、合规、场地、时间）。写不出「为什么必须补」的即为加戏，删掉。

NARRATE · 叙事装配

按 SCQA 组织，每节首句必须是判断，判断后紧跟证据标记；上一节结论即下一节问题。禁止「下表展示了……」开头。

🚀快速开始

三步装上，然后直接说需求

bash / powershell
# 1. 克隆仓库
git clone https://github.com/Songyuanhong-nnn/Banana_RD-Skill.git
cd Banana_RD-Skill

# 2. 安装（Windows）
cd plugin
.\install.ps1

# 2. 安装（macOS / Linux）
cd plugin && ./install.sh

# 3. 自检
python ai-sq-universal/scripts/validate.py

# 质量门禁（可选，可接 CI）
python ai-sq-universal/scripts/quality_gate.py report.md \
  --json report.json --complexity 3 --risk high

然后直接说需求

它会先做什么

量词问题会先被消歧（「这份合同有几段」），然后定复杂度档位、建问题树，再决定要展开多少——而不是一上来就写。

交付什么

写作在 Markdown（模型好改），交付是 Word（读者要打开）。封面、目录、页眉页脚、斑马纹表格、可点击引用，另出 JSON 供机检。禁止手工另存 Word——那是文档与结论漂移的根源。
