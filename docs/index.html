一个调研 Skill结论可核验，追问答得上

给它一个题目，它按固定流程查证、铺面、验伪，交付一份 Word 报告—— 每条结论定位到原文那一句，每个数字都有出处， 没查到的地方写明没查到，对方会问的问题提前备好答案。

三步装上 读主规范 SKILL.md

合格的调研不是「看起来查过了」，是随便挑一条结论，30 秒内能翻到它出自哪一句。

它解决的问题

AI 写的调研报告，大多经不起三句追问

不是不全面，是全面得没法验。下面三种情况，只要出现一种，这份报告就不能拿去支撑决策。

01

数字没有出处，或者出处在二手转述

「据某行业报告，渗透率约 30%」——报告名没有、页码没有、原文句没有。一个编造的引文和一个真实的引文，读起来一模一样，唯一区别是它定位不到。

02

该问的没问，被问住就空了

报告写了 40 页，对方开口三句：「凭什么信」「成本超支怎么办」「为什么不选另一条」——一个都答不上。内容全 ≠ 答得上追问。

03

把「没查到」写成「不存在」

检索不到就下结论说不存在，读者无法分辨哪部分查过了、哪部分压根没查。看起来饱和，实际漏了整类因素。

四条硬约束

不靠模型自觉，靠规则卡住

每条规则都对应一个真实发生过的失败模式，并且写进了可执行的质量门禁——不合格会直接判 FAIL，不是「建议」。

RULE 01引用到那一句

必须给定位（页 / 段 / 条 / 表行 / 时间戳）+ 逐字原句 + 上下文。二手转述按最弱一环定级；公众号只作线索，不作结论。

RULE 02数字必须有出处

任何百分数、金额、倍数必须来自引用。禁止「约 80%」「多数」「大幅提升」；不同口径的数字不可直接比。

RULE 03没查的必须写明

8 条覆盖判据逐条交代，含负空间：按常识该有、但没找到的因素。缺一条就不许说「已系统覆盖」。

RULE 04判定路径要写出来

报告必须有「节点 + 判定条件 + 成立/不成立分支 + 终局」的主路径。走不通的分支要写终止原因与替代路径。

深度可选

先定档，再决定查多细

防止两种失败同时发生：简单问题被过度展开成八股，复杂问题被草草扫过。 开工前会跟你确认档位；问不到或你说「你定」，默认按 L4 全量跑。

L1只要结论
单一主因 → 主果，且已做分层 / 交互检查未发现反号。 做：九层追问链 + 反例
L2多因素
≥3 个相对独立因素，检验未发现反号。 加做：因素空间 + 量级 + 共线 / 混杂初查
L3交互 / 异质
分层后反号、联合效应非可加、阈值 / 非线性、案例间机制不同。 加做：交互矩阵 + 分层矩阵
L4全量
因果图有双向边、双向时间证据、已知时滞、regime shift。 加做：因果图 + 时滞 + 情景分析 + 附录 A 问答预案

预算不足不降档：把没做完的项标 unchecked，而不是悄悄当成「不需要查」。

适用边界

什么该用它，什么别硬套

判据不是「问题长不长」，而是三件事同时成立：结论能由公开可检索证据支撑、答错有代价、允许花时间。缺一条就该降级用法。

适合

  • 科学机制 / 技术选型 —— 结论落在一手层，证伪路径公开
  • 法律条文 / 政策文件 —— 强在条文与文件检索
  • 金融披露 / 商业分析 —— 强在公开披露与可比口径
  • 历史史料 —— 可用史料批判证伪
  • 产业方向 / 设备选型 —— 多因素铺面 + 量级可比
共同点：答案在公开域，且能被一条具体证据推翻。

不适合

  • 数学证明 / 代码推导 —— 纯演绎，没有「证据」这回事
  • 审美与价值判断 —— 无可证伪 claim
  • 实时行情 / 天气 / 比分 —— 时间预算不允许
  • 医学临床决策 / 私有系统故障 —— 变量在私有数据里，检索拿不到
  • 内部数据 / 一手实验 —— 证据不在公开域
共同点：缺一条判据，就只能做背景梳理或假设生成，不能当结论用。
开始用

三步装上，然后直接说需求

bash / powershell
# 1. 克隆仓库
git clone https://github.com/Songyuanhong-nnn/Banana_Research-Skill.git
cd Banana_Research-Skill

# 2. 安装（Windows）
cd plugin
.\install.ps1

# 2. 安装（macOS / Linux）
cd plugin && ./install.sh

# 3. 自检
python ai-sq-universal/scripts/validate.py

# 质量门禁（可选，可接 CI）
python ai-sq-universal/scripts/quality_gate.py report.md \
  --json report.json --complexity 3 --risk high
