# 读者提问预判 / Anticipated Questions

**第八套覆盖。** 前七套管的是"内容全不全、深不深、路径通不通、证据硬不硬"，都不管一件事：

> **客户当场会怎么问？我答不答得上？**

报告合格 ≠ 答得上追问。评审现场最尴尬的不是"某项没查到"，而是"你写了这一段，但被问了三个问题就空了"。

---

## 1. 生成方法：角色 × 问型矩阵（禁止拍脑袋列"常见问题"）

**5 类角色**：决策者 / 付费者 / 使用者 / 被影响者 / 守门人。
**6 种问型**：是什么（定义）/ 为什么（机制）/ 凭什么信（证据）/ 对我什么影响（风险与收益）/ 多少钱多久（成本与时点）/ 不行怎么办（替代与退出）。

逐格生成，**每格至少一条具体问题**（30 格，允许合并，但不许整行空白）：

| | 是什么 | 为什么 | 凭什么信 | 什么影响 | 多少钱多久 | 不行怎么办 |
|---|---|---|---|---|---|---|
| 决策者 | 这到底是什么事 | 为什么会这样 | 依据哪份文件 | 批了会怎样 | 要投多少、多久见效 | 不批会怎样 |
| 付费者 | 买的是什么 | 为什么值这个钱 | 谁给的数据 | 超支风险 | 预算与回收期 | 能不能先不买 |
| 使用者 | 具体怎么操作 | 为什么要这么操作 | 判读标准是什么 | 出错谁负责 | 培训多久 | 设备坏了怎么办 |
| 被影响者 | 我会受什么影响 | 为什么会波及我 | 有先例吗 | 最坏情况 | 补偿/替代 | 能不能拒绝 |
| 守门人 | 属哪一类管理 | 为什么要管 | 依据哪条法规 | 不合规的后果 | 审批周期 | 能不能豁免 |

**再加一轮"残酷追问"（敌对视角，12 条）**：反例是什么 / 谁失败过 / 成本会不会超 / 人员够不够 / 时间来得及吗 / 会不会被替代 / 责任归谁 / 最坏情况 / 如果判断错了怎么办 / 为什么不选另一条路 / 数据能复现吗 / 结论变了谁负责。

---

## 2. 每题必须有状态，不许留白

| 状态 | 含义 | 要求 |
|---|---|---|
| `ANSWERED` | 能答，且有依据 | 必须带引用编号 |
| `PARTIAL` | 能答一部分 | 写清缺哪一块、缺的部分影响什么判断 |
| `UNANSWERED` | 答不上 | **必须写：缺口 + 补法 + 谁来补 + 补不到时的应对话术** |

**规则：**
- **不允许空白题**。答不上就写"答不上 + 补法"，这比含糊带过诚实，也比现场被问住好。
- **关键决策类问题（决策者 × 是什么/凭什么信/不行怎么办）必须 `ANSWERED`**；做不到就说明本报告的结论还不够。
- 全文 `ANSWERED` 比例 ≥70%；`UNANSWERED` 必须进报告"局限与未决"。
- **预案是自答，不是把问题推回给客户。** 报告里不出现"待与客户确认的问题清单"。

---

## 3. 输出格式（写进附录 A）

```markdown
| Q# | 问题 | 谁问 | 他为什么问 | 回答要点 | 引用 | 状态 |
|---|---|---|---|---|---|---|
| Q1 | 带毒株对人有没有风险？ | 守门人 | 决定是否需要员工防护 | 现有证据显示…；对人的风险标志是… | 〔3〕〔7〕 | PARTIAL |
```

末尾给统计与未答清单：

```
覆盖统计：角色×问型 30 格已覆盖 n 格；ANSWERED a / PARTIAL p / UNANSWERED u
未答清单：Q7（缺口…；补法…；补不到时说…）
```

---

## 4. 与其他覆盖的关系（不要重复劳动）

| 机制 | 覆盖什么 | 视角 |
|---|---|---|
| 九层链 | 一条线挖多深 | 对象 |
| 因素九轴 | 一个结果的因素类型 | 因果 |
| 14 维总纲 | 要回答哪些问题面 | 决策面 |
| 判定路径 | 从起点到终局怎么走 | 过程 |
| **问答预案** | **读者会怎么问、能否答上** | **读者** |

问答预案不能替代前四者；它的作用是**用读者的嘴把报告过一遍**，把"写了但答不上"的地方暴露出来。

---

## 5. 反模式

| 反模式 | 问题 |
|---|---|
| 只列 5 个"常见问题" | 没按角色×问型铺，漏掉真正会问的人 |
| 答案没有引用 | 现场一追问就露 |
| 用"需进一步研究"当答案 | 等于承认没准备 |
| 只写温和问题，不写敌对追问 | 评审最爱问的恰恰是反例与失败案例 |
| 把预案写成"要问客户的问题" | 方向反了：预案是自答 |
