# 写作与呈现标准 / Writing & Presentation Standard

**这份文件管"报告长什么样、结论凭什么站得住"。它优先于任何模板的美观偏好。**

---

## 1. 结论即主张：每条都要能溯源

### 1.1 三类句子，三种处理

| 类型 | 判据 | 处理 |
|---|---|---|
| **结论**（可被引用去支持决定） | 有明确判断、能被证伪 | **必须带编号引用**，如「…因此只能作预警〔C3〕」 |
| **过程**（怎么查的、为什么这样查） | 描述方法 | 可无引用，但须写清"查了什么、没查到什么" |
| **推测**（有理由但无直接证据） | 尚无来源 | 必须显式标「**推断**」并给出推断依据；不得与结论混排 |

**禁止**：把推测写成结论。**禁止**：结论没有引用。

### 1.2 数字规则（最常被糊弄的地方）

- **任何**百分数、金额、倍数、比例、排名，**必须来自引用**；句中无引用 → 该数字不允许出现。
- **禁止无来源的模糊量词**：「约 80%」「多数」「大部分」「显著提升」——除非来源原文如此，且照样要带引用。
- 引用里的数字要**连口径一起搬**：是样品还是增菌液、是峰值还是持续、含税还是不含税。口径不同的两个数字**不能放在一起比较**。
- **禁止二次换算后当原文**：把"1000 CFU/mL（增菌液）"改写成"样品检出限 1000 CFU/mL"就是造假。

> 反例（必须删）：「常规手段足够解决 80% 的现场问题」——这个 80% 没有来源，读者无法核。改成引用支撑的分级判断，或写成「在检索到的 X 篇报告中，Y 篇支持…〔C1〕〔C4〕」。

### 1.3 引用编号与链接

- 正文用方括号编号：`〔1〕〔3〕`（或 `[C3]`，全文统一）。
- **每个编号必须对应到可点击链接**；交付 Word 时由脚本自动转超链接，正文不得只写"某报告"。
- 参考文献表逐条给：作者/机构 · 标题 · 载体 · 日期 · **定位（页/段/条/表行）** · URL。

## 2. 排版：像文献，不像仪表盘

### 2.1 必须做到的

- **章节编号**：1. / 1.1 / 1.1.1；不用装饰性符号。
- **表**：表题在上（"表 3 三种检测路线对比"），来源注在下（"来源：〔5〕，经作者整理"）。
- **图**：图题在下；坐标轴与单位必须标。
- **术语**：首次出现给中英文对照；缩写首次出现给全称。
- **人称**：陈述句，不写"我们认为""让我们来看看"。

### 2.2 禁止的"AI 腔"（见到就删）

| 禁止项 | 为什么 |
|---|---|
| emoji / ✅⚠️❌ / 装饰符号 | 文献不用；且会破坏"可核查"的观感 |
| 「明天该问对方的 N 个问题」 | 报告是交付物，不是待办清单；有疑问要给**预置假设与应对**，不是把问题推回给对方 |
| 「本报告不保证…」「避免过度承诺」套话 | 除非法律/合规要求，否则是废话；不确定性写进具体结论的限定条件 |
| 「修正一 / 修正二 / 我之前说错了」 | 读者只关心结论与其来源；过程纠错属工作记录，不进报告 |
| 「综合来看」「多方面因素」「机遇与挑战并存」 | 信息量为零，等于没判断 |
| 「让我们」「接下来我们」 | 口语，且把读者当听众而不是读者 |
| 通篇项目符号代替论述 | 没有因果链，读者读不出为什么 |

### 2.3 版式参数（Word 交付）

正文宋体 10.5pt / 1.5 倍行距；标题微软雅黑；页边距上 2.2 / 下 2.0 / 左 2.4 / 右 2.2 cm；页脚「第 X 页 / 共 Y 页」。表格字号 ≤9pt，跨页重复表头。

## 3. 结构：一条主路径，不是十四个抽屉

**报告不是"维度清单"，是一条从起点走到终局的路。**

```
起点：委托意图（他要达成什么）
  ↓
判定节点 1 ──成立──→ 分支 A ──→ 下一节点
  │            └─不成立→ 分支 B（终局或改道）
  ↓
判定节点 2 …（同上）
  ↓
终局：成功 / 失败 / 条件性成立（给出触发条件与监控指标）
```

**要求：**
1. 报告必须有一节「**判定路径**」，用节点表或树图给出**主路径**；每个节点写：判定问题、判定条件、成立/不成立各走向、依据编号。
2. 后续章节按**路径顺序**推进，而不是按"技术/市场/政策"并列罗列。
3. **每个分支都要给出"如果走错会怎样"**——这正是委托方最需要的部分。
4. 一条路径走不通时，明确写"此路终止，原因 + 替代路径"，不要含糊带过。

**判定节点表格式**

| 节点 | 判定问题 | 判定条件 | 成立→ | 不成立→ | 依据 |
|---|---|---|---|---|---|
| N1 | 现有能力能否识别带毒株？ | 有 qPCR 且能做 pirAB | N2 | 先建 qPCR 或改送检 | 〔3〕 |

## 4. 意图优先：先读懂人，再谈方法

**用户给一段话时，先做三件事，而不是把它当调研范围：**

1. **复述意图**：他要拿这个结果去做什么？（决定/汇报/立项/对外答复/自用）
2. **识别判断标准**：什么结果他会认为"有用"？什么会让他觉得"白做"？
3. **再定范围**：他的列举是**下限**，不是上限。

**禁止自造决策场景。** 把"公司需要决定是否采购某设备"这类模板套在用户身上，是最常见的误读——用户可能只是想知道"这事到底怎么回事"。

**意图不明时**：写「意图假设」并给出**两条可能路径**（若为 A 则……若为 B 则……），而不是编一个场景当成事实。

## 5. 交付前自检（逐条过）

- [ ] 每条结论都有引用编号，且编号可点开
- [ ] 文中每个百分数/金额/倍数都能在参考文献里找到出处与口径
- [ ] 没有 emoji、没有"该问对方的 N 个问题"、没有"修正"段、没有"避免过度承诺"
- [ ] 有一条明确的判定路径（节点 + 分支 + 终局）
- [ ] 每节首句是判断，不是"下表展示了"
- [ ] 表有表题与来源注，图有图题与单位
- [ ] 术语首次出现有中英对照
- [ ] 读一遍全文：删掉所有"删了也不影响读者判断"的句子
