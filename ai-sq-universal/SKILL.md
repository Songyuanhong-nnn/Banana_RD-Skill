# AI-SQ Universal Root-Inquiry / 通用求根问底调研

**一句话内核：**
**求根问底 = 问题树 × 证据链 × 缺口递归 × 因素空间 × 范围与反例 × 层级校验 × 覆盖饱和 × 停止控制 × 结构化报告。**

不是"一直追问"，而是：每问必有缺口，每答必有证据，每层必有范围，每结论必有反例检查，每轮必有停止条件。

---

## 0. 它保证什么、不保证什么

**保证：** 结论可追溯（有 ID、有原文句、有等级）；范围被检验（对谁成立、在什么条件下不成立）；因素被枚举（不是只挖到一条链就交卷）；停止有理由（能区分"查完了"和"查不下去了"）。

**不保证：**

| 它做不到 | 因为 | 你该怎么做 |
|---|---|---|
| 给出可执行的专业决定 | 它只整理公开证据，不承担执业责任 | 医学/法律/金融决策交执业者 |
| 产生一手数据 | 它检索，不做实验、不做访谈 | 需实验的问题标 `needs_human` |
| 解演绎问题 | 数学证明、代码推导不靠检索 | 用推理或跑代码 |
| 判断审美与价值 | 没有客观证据链 | 用别的工具，别用这个 |
| 在秒级给出答案 | 预算 10 分钟起 | 实时决策用别的路径 |

**为什么要把这些写死：** v2.0 曾说"适用于所有领域"。那句话违反了本文件 §4 的第 5 条原则（出现"所有"必须查反例）——一个不做反例检查的绝对断言，正是这个 Skill 要防的错误。领域适配度的真实分布见 `references/domain_fit.md`。

---

## 1. 什么时候用 / 不用

**用**：需要机制解释、**因素清单与影响量级**、范围界定、争议梳理、反例边界、最新进展；或结论要为决策负责、必须能复核。

**不用**：单一事实查询、实时行情、纯创意写作、数学证明、已有定论且无需追溯的常识。

判据不是"问题长不长"，而是三件事同时成立：**结论能由公开可检索证据支撑、答错有代价、允许花时间**。缺一条就降级用法（只做背景梳理，或只做假设生成）。

---

## 2. 一次运行的十三步

```
INIT → BRIEF → AMBIGUITY_CHECK → SCOPE → COMPLEXITY → PLAN → RETRIEVE → EXTRACT
     → VERIFY → ANSWER_NODE → EXPAND_GAPS → FACTOR_SPACE → STOP_CHECK → NARRATE → REPORT
```

| 步 | 动作 | 防止 |
|---|---|---|
| INIT | 定 target/goal/domain/预算 | 用错目标 |
| **BRIEF** | **目的五问 + 五类相关方**（§2.5）；写进报告 §0 | **精确但无用：没人能据此行动** |
| **SCOPE** | **需求外扩审计**：用户列举是下限不是上限（§2.5） | **只答被问到的，漏掉决定成败的变量** |
| AMBIGUITY_CHECK | 对象/目标/深度/量词歧义先消解或声明假设 | "几段"答错维度 |
| **COMPLEXITY** | 判定 L1–L4（见 §3），**它决定后面展开到多细** | 简单问题过度展开、复杂问题草草扫过 |
| PLAN | ≤12 个一级节点覆盖九层（§4） | 空泛提问 |
| RETRIEVE | 按领域包源优先级检索 | 拿百科当结论 |
| EXTRACT | `quote` 逐字保留 | 结论被悄悄放大 |
| VERIFY | 六项基础检查（§9 of prompts/verifier.md） | 类别套实例、相关当因果 |
| ANSWER_NODE | 答案 + 置信度 + 证据 ID + 缺口 | 无据断言 |
| EXPAND_GAPS | 一条缺口一条问题，≤5 条，去重 | 无限追问 |
| **FACTOR_SPACE** | 横切铺开因素：轴枚举 → 量级 → 交互 → 分层（§5–§7） | **只挖一条链就交卷** |
| STOP_CHECK | 停止规则 + 覆盖饱和（§8、§13） | 把"没查完"伪装成"查清了" |
| REPORT | Markdown 十四节 + JSON | 不可复核 |

**每轮必答五问**：已知什么？缺什么？下一问是什么？为什么问它、查什么源？何时停？

---

## 2.5 目的与受益方（BRIEF）与需求外扩（SCOPE）

**这是全流程的第一道硬闸：没写清"为谁而答、支撑什么决定"，就不许开始检索。** 详见 `references/brief_and_stakeholders.md`。

**目的五问（写进报告 §0）**：支撑什么决定 / 何时要 / 答错谁受损多大 / 怎样算合格 / **明确不做什么**。
没有决定的调研也要写明"仅建立认知基线"，并把深度预算降到最低——没有决定的调研最容易无限膨胀。

**五类相关方（缺哪类必须写"为何不适用"）**：

| 决策者 | 付费者 | 使用者 | 被影响者 | 守门人 |
|---|---|---|---|---|
| 要签什么？要多大的阈值与反转条件 | 出多少钱？看 TCO 还是单价 | 谁执行？要 SOP 还是只要结论 | 谁承担后果（一线/社区/下游） | 谁能否决（合规/评审）？要什么依据 |

用户通常只说得出前两类。**使用者、被影响者、守门人必须由你主动补齐**——它们是落地失败的高发点（买得起用不起、合规过不了、一线不执行）。

**受益方要贯穿每一部分，不是开头提一次。** 每个结论必须带三样：

| 字段 | 回答什么 |
|---|---|
| `serves` | 这条结论对**谁**最有用 |
| `action` | 他要据此**做什么动作** |
| `if_wrong` | 信错了**代价**是什么 |

**自检**：删掉这条结论，哪个角色的哪个动作会变？**没有动作会变 → 这条是噪音，删掉或降为附录。**

**需求外扩审计（SCOPE）**：用户说"我要查 A、B、C"，不等于只需要 A、B、C。三类缺口必须过一遍：

| 缺口类型 | 判据 | 处理 |
|---|---|---|
| **必要遗漏** | 不答它，A/B/C 的结论就不成立 | 必须补，写进报告 |
| **目的错位** | 用户问的是手段，真实目的是结果 | 挑明目的，可能给出更省钱的替代方案 |
| **成败变量** | 用户没提，但决定能否落地（预算/人员/合规/场地/时间） | 至少列出并标注影响 |

**外扩不等于无限扩**：每条外扩都要写"为什么必须补"，写不出来的就是加戏，删掉。

## 3. 复杂度分级：先定档，再决定展开多少

同样是"调研"，L1 和 L4 的工作量差一个数量级。**先判档，避免两种典型失败：把简单问题写成八股，或把复杂问题压成一句话。**

| 档 | 结构判据（看结构，不看因素多少） | 必做检查 | 预算 |
|---|---|---|---|
| **L1 单链** | 单一主因 → 主果；时序清楚；**且已完成分层/交互检查、未发现反号** | 九层链 + 反例，**不建因素空间** | 6 层 / 15 节点 |
| **L2 多因素并列** | 结果受 ≥3 个相对独立因素影响，**且分层/交互检验未发现反号**（未检验者不得定本档） | 因素空间（§5）+ 量级 + 共线/混杂初查 | 6 层 / 25 节点 |
| **L3 交互/异质** | 任一：分层后效应反号或幅度差异大；两因素联合效应非可加；存在阈值/非线性；不同案例机制不同 | L2 + 交互矩阵（§7）+ 分层矩阵（§6） | 7 层 / 35 节点 |
| **L4 动态系统** | 任一：因果图存在**双向边**；同一变量对有两个方向的时间证据；已知时滞/累积；已知 regime shift | L3 + 因果图 + 时滞分析 + 情景分析 + 模型局限三字段 | 8 层 / 45 节点 |

**判档问句**：因果图上有没有双向边？同一个变量对有没有两个方向的时间证据？有 → L4。把某一个因素改掉，结论会不会变？会且不止一个 → L2 起。两个因素一起改才是关键 → L3。

**五条硬规则：**

1. **档位与因素数量正交。** 因素多但全线性 = L2；因素少但有强反馈 = L4。把"因素多"当"复杂"会严重低估动态性。
2. **"没查到反号"不等于"没有反号"。** 未做分层/交互检验就没有资格定 L1/L2，按高一档处理，并在 `gaps` 写"交互/异质性未检验"。这条专治把"没查"读成"没有"——它正是"看起来全面"的主要来源。
3. **档位 ≠ 完成度。** 档位决定"必须做哪些检查"，预算决定"这次做完几项"。预算不足时**不降档**，把未完成项标 `unchecked` 写进 §14。降档会让"没查"悄悄变成"不需要查"。
4. **判错档的代价不对称。** 低估（L3 当 L1）会产出"看起来有理、一换情境就错"的结论；高估只是浪费预算。所以存疑取高。
5. **L4 最小声明三字段**：外推边界 / 被省略的回路 / 参数敏感性区间及取值来源。写不出这三项，不允许写 L4 结论。

## 4. 九层追问链（纵切：把一条线挖到底）

| # | 层 | 要回答的问题 | 典型 question_type |
|---|---|---|---|
| 1 | 定义与归属 | A 是什么？属于哪类？上位/下位/近邻是谁？ | `definition` `taxonomy` |
| 2 | 属性与范围 | 有哪些关键属性？是否都成立？对谁、在什么条件下成立？反例是什么？ | `attribute` `scope` `counterexample` |
| 3 | 机制与因果 | 由什么导致？因果链、必要条件、充分条件、促进因素 | `mechanism` `causal_chain` |
| 4 | 载体与要素 | 承载在什么载体上？具体要素清单是什么？ | `carrier` `element_inventory` |
| 5 | 结构与参数 | 数量、层级、组成、条款、模块、阶段、拷贝、版本、变体、参数 | `structure` `parameter` |
| 6 | 功能与影响 | 起什么作用？对谁？多强？剂量与边界 | `function` |
| 7 | 调控与约束 | 受什么调控、监管、约束、依赖、反馈？例外？ | `regulation` |
| 8 | 证据与争议 | 证据等级？多源一致？冲突、空白、不确定性 | `evidence` `controversy` |
| 9 | 前沿与下一步 | 最新进展？未解问题？下一步查什么 | `frontier` `next_step` |

**硬要求：**

- 出现"都/所有/一定/必然/唯一/总是"→ 必须查反例（第 2 层）。
- 第 5 层的量词先消歧（"段"指什么），否则答错维度。
- 九层可按 goal 裁剪，但要**写明砍了哪层、为什么**。

**九层的天花板：** 它保证"一条链挖得深"，**不保证"因素枚举得全"**。真实问题通常是"很多因素共同作用"，这时光有链会漏掉整整几类因素。这就是 §5–§7 存在的原因。

## 5. 因素空间（横切：把一个结果的因素铺开）

对 L2 及以上，九层链之后必须建因素空间。它回答的是：**"这个结果 Y，到底被哪些东西影响？各自多强？"**

### 5.1 按九轴枚举，防止整类漏掉

不要凭记忆想因素——记忆只会重复你已经想到的那几类。按轴逐个过，每轴至少问一遍，**空轴要写"空，理由"**：

| 轴 | 该问什么 | 最容易漏 |
|---|---|---|
| 时间 | 起源、阶段、时滞、累积、演化 | 把横截面数据当因果（看不见时滞） |
| 空间/层级 | 分子→细胞→个体→群体→制度→全球，各层是否都有因素 | 生态谬误（群体结论套个体） |
| 主体 | 行为者、利益相关方、权力与激励结构 | 只算"客观因素"，漏掉"谁在决策" |
| 物质/资源 | 能量、资金、材料、算力、人力、供给约束 | 把资源约束当成"其他条件不变" |
| 规则/制度 | 法律、规范、激励、准入、监管 | 忽略制度变化导致的效应反转 |
| 信息/认知 | 知识、信息不对称、预期、偏差 | 假设主体全知理性 |
| 技术/工具 | 能力、成本、可用性、成熟度 | 忽略技术代际差异 |
| 环境/外部冲击 | 气候、市场、地缘、随机事件 | 把一次性冲击写成结构性原因 |
| 反馈/动态 | 正反馈、负反馈、锁定、相变、临界点 | 静态框架看不见动态 |

### 5.2 每个因素必须带的字段

```json
{
  "factor_id": "F1",
  "name": "志贺毒素（Stx2）表达",
  "axis": "物质/资源",
  "entity_level": "protein_effector",
  "role": "necessary|sufficient|contributing|inhibiting|threshold|moderator|mediator|confounder",
  "direction": "+|-|±",
  "magnitude": "dominant|major|minor|unknown",
  "magnitude_basis": "为何是这个量级：效应量/必要条件/专家共识/多源一致",
  "proxy": "可观测代理（能测什么代表它）",
  "evidence_ids": ["E1", "E4"],
  "evidence_grade": "A|B|C|D",
  "how_to_test": "怎样验证它真的起作用"
}
```

### 5.3 量级是硬要求，不是加分项

**列出 30 个因素而不说哪个是主因，等于没回答问题。** 量级四级：

- `dominant`：单独能解释大部分结果，或是必要条件（去掉它结果不发生）
- `major`：显著改变结果幅度，但不决定有无
- `minor`：影响可测但有限
- `unknown`：**必须写清为什么不知道**（无量化研究 / 证据冲突 / 无法观测）

禁止的写法：把因素排成一个无差别的清单，然后说"这些都很重要"。这句话在信息量上等于零。

## 6. 分层矩阵（切面：同一因素在不同情境下不同）

L3 起必须做。做法：选定 1–3 个**关键分层维度**（法域、菌株、人群、时期、规模、渠道…），把主导因素逐层切开回答。

| 因素 | 分层 A（如：儿童） | 分层 B（如：成人） | 分层 C（如：免疫抑制） | 是否反向 |
|---|---|---|---|---|
| F1 剂量效应 | 强 | 中 | 极强 | 否 |
| F3 抗生素使用 | 风险↑ | 风险↑ | 证据不足 | — |

**为什么必须做：** "同一因素在不同分层效应相反"（effect modification）是多因素问题最容易被抹平的地方。抹平它的后果比"不知道"更严重——因为它会产出一个对所有人都错、却对所有人都显得合理的结论。

**分层维度的选择要有依据**：来自领域包 `structure_semantics` 的 `variant`、来自文献中的已知效应修饰因子、或来自用户的实际情境。没有依据地分层会制造伪精度。

---

## 7. 交互与混杂（复杂度：因素之间不独立）

L3 起必须做，L4 还要加时间与反馈。逐项检查（识别方法见 `references/complexity_patterns.md`）：

| 要检查 | 问句 | 漏掉的后果 |
|---|---|---|
| 混杂 confounding | 是否存在同时影响 A 与 Y 的第三因素，且在样本中分布不均？ | 把相关当因果 |
| 中介 mediation | A 是通过 M 影响 Y 的吗？直接效应与间接效应各多少？ | 归因给错误的环节 |
| 调节/效应修饰 | 哪个变量改变 A→Y 的强度或方向？ | 平均效应掩盖反向亚组 |
| 交互 interaction | 两因素同时存在时，效应是否大于/小于各自之和？ | 低估组合风险 |
| 对撞 collider | 是否只看了某个被共同结果筛选过的子样本？ | 制造虚假相关 |
| 反馈 feedback | Y 是否反过来影响 A？ | 静态结论在动态系统里失效 |
| 时滞 lag | 因素作用到显现之间隔多久？ | 把未显现误判为无效应 |
| 阈值/非线性 | 是否存在临界点，超过后效应突变？ | 线性外推 |
| 生态谬误 | 结论是在群体层还是个体层得出的？ | 跨层误用 |

**输出要求**：只列确有证据或高度可疑的交互，并标注 `confirmed` / `suspected` / `checked-none`。**"检查过且没有"也要写**，否则读者无法区分"没查"和"查了没有"。

## 8. 覆盖饱和：怎么知道"方方面面"够了

这是"全面"的验收标准。**没有验收标准的"全面"只是自我感觉。** 七条全部满足才可声称覆盖：

1. **轴覆盖**：9 轴逐一走过，每轴有因素或写明"空，理由"。
2. **量级覆盖**：每个因素有 `magnitude`，`unknown` 必须带原因。
3. **饱和判据**：连续 2 轮检索/展开无新因素、无新轴。
4. **负空间检查**：列出"按常识应该存在、但我没找到"的因素 —— 它们往往才是最大的漏洞。
5. **交互检查**：量级为 `dominant`/`major` 的因素，两两交互已检查。
6. **分层检查**：量级为 `dominant`/`major` 的因素，两两交互已检查；至少 2 个关键分层上是否反向已查。
7. **维度覆盖**：14 维按对象类型激活，逐维标注 已答 / 不适用（理由）/ 未查；未查项进负空间。

任何一条不满足，报告必须写"覆盖不完整 + 缺哪条"，而不是含糊地说"已全面分析"。

## 8.5 第三套覆盖：维度总纲（14 个问题面）

九层链管"单个问题多深"，九轴管"单个结果的因素类型"，**但两者都不管"调研对象要回答哪些问题面"**。真实调研是以决策为中心铺开的：投资人问市场，工程师问性能余量，采购问总拥有成本，法务问合规边界。少一维，报告在某一类读者眼里就是残缺的。

`references/dimension_outline.md` 给出 14 维总纲，每维含：必答问题 / 需要什么材料 / **典型困难（分支就从这里长出来）** / 最低证据 / 何时判 unknown。

| # | 维度 | # | 维度 |
|---|---|---|---|
| D1 | 目标与决策场景 | D8 | 政策、法规与标准 |
| D2 | 定义、边界与口径 | D9 | 主体、激励与采购链条 |
| D3 | 性能与技术能力 | D10 | 时间、阶段与路线图 |
| D4 | 经济性（TCO） | D11 | 风险、失败模式与反例 |
| D5 | 市场与需求 | D12 | 证据质量与争议 |
| D6 | 竞争与同行 | D13 | 决策含义与替代方案 |
| D7 | 供应链、产能与交付 | D14 | 未解、负空间与下一步 |

**用法**：先按对象类型激活必选维度（选择器见该文件 §4），逐维回答，**未激活的维度必须写"为何不选"**——写不出理由，通常只是没想到。

**四轮遗漏自检**（"重复去查"的机制）：R1 维度级（14 维逐一勾选）→ R2 因素级（九轴）→ R3 反例级（15 模式 + 退出者/失败案例专项）→ R4 负空间级（该有但没有的）。连续两轮零新增才可声明饱和；一轮零新增只是"这轮没找到"。

## 9. 领域适配层

领域包不是装饰，而是适配接口。没有领域包 → 用通用实体层级与证据标准；有领域包 → 领域包优先，但**不得绕过**反例、层级、停止、覆盖规则。

| 字段 | 作用 | 不定义会怎样 |
|---|---|---|
| `entity_levels` | 实体层级（粗→细） | 载体当要素、产物当原因 |
| `structure_semantics` | "段/拷贝/变体"指什么 | "几段"答错维度 |
| `authoritative_sources` | 权威源与优先级 | 拿百科当结论 |
| `evidence_grades` | A/B/C/D 的领域细化 | 证据等级失效 |
| `counterexample_rule` | 该领域必查的反例 | 结论范围虚高 |
| `high_risk` | 高风险边界 | 越界建议 |

**已装**：`science`（含 `sub_packs.bacteriology`）、`law`、`finance`、`history`、`technology`、`policy`、`business`。

**细菌致病性只是一个包。** 它不提供流程，只提供词汇（物种/菌株/血清型/毒力基因/致病岛/分泌系统）与反例规则（携带毒力基因 ≠ 表达 ≠ 致病）。换 `law.yaml`，同一内核就变成法条竞合调研。这就是"通用"的可验证含义。**领域适配度的真实分布（含不适用）见 `references/domain_fit.md`。**

新增领域包：见 `domain_packs/README.md`，用 `python scripts/validate.py --packs` 校验。

## 10. 问题节点与优先级

完整字段见 `schemas/question_node.json`。去重键：`question_type | entity | relation | scope | qualifier`。没有去重键，递归会退化成同义反复。

```
priority = 0.30 × 与目标相关度
         + 0.25 × 不确定性
         + 0.20 × 证据缺口
         + 0.15 × 下游影响
         + 0.10 × 用户显式追问
         - 0.10 × 预计成本
```

因素节点另有一个 `factor_priority = 方向 × 量级 × 证据强度`，用于决定先补哪个因素：**量级大且证据弱的因素，回报最高。**

## 11. 递归算法

```python
def run(target, params):
    level = assess_complexity(target, params)          # L1-L4
    root = make_root(target, params)
    frontier, seen = [root], set()

    while frontier and budget_ok(params):
        node = select_node(frontier)
        frontier.remove(node)

        key = canonical_key(node)
        if key in seen:
            continue
        seen.add(key)

        docs     = retrieve(build_queries(node, params.domain), params.domain)
        facts    = extract(docs, node)                 # 保留原文句 + 来源 ID
        verified = verify(facts, node, params.domain)

        node.answer       = synthesize(verified)
        node.confidence   = estimate_confidence(verified)
        node.evidence_ids = [f.evidence_id for f in verified]
        node.gaps         = find_gaps(node, verified)

        if node.question_type in ("attribute", "scope", "function"):
            check_counterexamples(node, params.domain)

        if needs_disambiguation(node):
            node.status = "needs_human"
            node.stop_reason = "歧义未消解"

        children = generate_questions(node.gaps, node, params.domain)
        node.children = children
        frontier.extend(children)

        if stop_node(node, params):
            node.status = "closed"
            node.stop_reason = node.stop_reason or "满足停止条件"

    factors = expand_factor_space(root, level, params)  # L2+；轴枚举 + 量级
    if level >= 3:
        check_interactions(factors, params)            # 混杂/交互/反馈
        build_strata(factors, params)                  # 分层矩阵
    coverage = check_saturation(factors, level)        # 七条覆盖判据

    return report(root, factors, coverage, params)
```

`expand` 只在**存在缺口**时产生子节点。无缺口即使深度未到也不再展开——这是"缺口驱动"与"层级驱动"的分水岭。

## 12. 证据等级

完整字段见 `schemas/evidence.json`。

| 等级 | 含义 | 用途 |
|---|---|---|
| **A** | 权威库/标准/法规/指南/官方统计 + 高质量系统综述，多源一致 | 支撑关键结论 |
| **B** | 同行评议原始研究、权威机构报告，方法可靠 | 支撑结论 |
| **C** | 预印本、行业报告、单一研究、数据库自动注释 | **只能作线索** |
| **D** | 百科、新闻、未验证网页 | **不作关键结论** |

**来源优先级**：领域权威库/标准/法规/指南 → 系统综述/元分析 → 同行评议原始研究 → 预印本/行业报告 → 百科/新闻/网页。

**为什么等级是硬约束：** 一旦允许 D 级支撑关键结论，任何结论都能"找到来源"，证据链随即失去区分力。等级的作用是让"没有 A/B 级证据"变成**必须写进报告的结论**（"未知"），而不是被悄悄填平。无 ID 即降级并标 `id_missing`；**编造 ID 比没有 ID 更糟**。

## 12.5 引用到句：证据的最小可核验单位

"有来源"不够。报告里最像证据、最不可靠的东西就是引用列表——**一段编造的引文读起来和真的一模一样，唯一区别是它定位不到**。所以标准不是"来源存在"，而是"这句话存在、在这个位置、上下文是这个意思"。

**八件必备**（`schemas/citation.json`）：来源类型、主体/作者、标题、发布日、**定位**、**逐字原句**、上下文、等级 —— 外加 `chain_length`（1=读到原文，2=引用转述）与 `verified_by`。

**四条硬规则：**

1. **关键结论必须到句。** 定位（页码/段落/条款/表格行/时间戳）+ 逐字原句，缺一不可。只给链接、只给报告名、"某公众号"一律不合格。
2. **二手按最弱一环定级。** 公众号转述论文 = 按公众号定 C/D，不按论文定 A；并且**必须尝试回溯一手**，失败要写明失败在哪。
3. **公众号/媒体只能作线索。** 可以引用，但定位到具体段落，并说明它转述的是谁；不得作为关键结论的唯一依据。**部门文件必须给文号 + 条款号 + 生效日**（并核对是否现行有效）。
4. **上下文防断章。** 至少一句前后文，或说明该句在回答什么问题。三种典型断章：原文是否定句、原文在举例反驳、原文说的是他人观点。

**没有"句子"的来源怎么办**（数据/数据库/访谈/内部文件）：

- 数据类：用 **库名 + 字段 + 期间 + 口径** 定位，记录取数时间与版本；
- 访谈/闭门会/内部文件：标 `unverified`，写明"不可公开复核"，**不进关键结论的证据链**；
- 付费墙只读到摘要：只引摘要句，不引未读全文里的具体数字。

**抽样核验**（机器做不了）：全查 A 级、关键结论依据、政策法条；随机抽 3 条 B 级按定位回查；专查所有 chain≥2 与 unverified。任一条找不到原句 → 同批复查并整体降级。

工具：`prompts/citation_auditor.md`（核验四问 + 六种作弊形态 + 抽样方法）。

## 13. 停止规则

**节点级**（满足任一即停当前分支）：

1. 已被 A/B 级证据闭合
2. 连续两轮无新实体、无新证据
3. 边际信息增益低于阈值
4. 达到深度/节点/时间预算
5. 只剩 C/D 级且无法升级
6. 冲突无法消解 → 保留争议
7. 高风险结论需人工复核
8. 超出可检索范围 → 标"需实验/专家/人工验证"
9. 歧义未消解 → 请求澄清或声明假设

**全局**（L2+ 额外要求）：所有高优先级节点关闭 **且** §8 七条覆盖判据满足 **或** 预算耗尽并写明缺口。

**每次停止写 `stop_reason`。** 没有停止理由的报告，等于把"没查完"伪装成"查清了"。

## 14. 报告与交付格式

模板见 `templates/report.md`。**交付物是 Word 文档**，Markdown 只是写作中间稿：

| 产物 | 作用 | 谁看 |
|---|---|---|
| `report.md` | 写作中间稿（便于模型逐段修改） | 不交付 |
| **`report.docx`** | **最终交付物**：封面/目录/页眉页脚/表格/可点击引用 | 人 |
| `report.json` | 机器可校验（符合 `schemas/report.json`） | 程序/复核 |

```bash
python scripts/build_docx.py report.md -o report.docx --title "报告标题"
# 多文件合订（封面 + 目录 + 分章）：
python scripts/build_docx.py --config docx_config.json
```

`build_docx.py` 支持：封面页、自动目录域、页眉页脚与页码、标题层级配色、斑马纹表格与重复表头、引用框（blockquote）、代码块、**裸 URL 自动转为可点击超链接**。生成后会重开校验一次，包损坏会报错而不是静默产出坏文件。

**为什么交付 Word 而不是 Markdown：** 读者打开的是 Word；而模型改 Markdown 最可靠。让两者来自同一份源文件（转换，而不是重打一遍），是避免"文档与结论漂移"的唯一办法。交付前必须跑一次 `build_docx.py`，不要手工另存。

```
调研对象 → 0 目的与受益方 → 1 一句话结论 → 2 定义与归属 → 3 属性与范围（含分层矩阵）
→ 4 机制与因果链 → 5 载体与要素清单 → 6 结构细节 → 7 功能/影响/调控
→ 8 反例与边界 → 9 证据与争议 → 10 前沿与未解问题 → 11 下一步追问
→ 12 证据表与参考文献 → 13 假设、歧义与免责声明 → 14 覆盖度与饱和声明
```

**第 14 节是 v2.1 的核心新增**：轴覆盖、量级覆盖、饱和、负空间、交互、分层、维度覆盖七项逐条交代。没有它，"全面"只是一个形容词。

JSON 不是附属品——它让每条结论、每个因素、每条证据、每个缺口都能被程序检查。

## 16. 失败模式

| 失败模式 | 表现 | 对策 |
|---|---|---|
| 无限追问 | 越问越空、同义反复 | 预算 + 去重键 + 边际增益停止 |
| **只挖一条链** | 机制讲得很深，但只覆盖一类因素 | 复杂度定档 + 因素空间 + 轴枚举 |
| **因素清单无差别** | 列 20 个因素，不说哪个是主因 | 强制 `magnitude` + `magnitude_basis` |
| **平均效应掩盖反向亚组** | "总体有效"但某人群无效 | 分层矩阵 + effect modification 检查 |
| **把相关当因果** | 混杂未检查 | 混杂/中介/对撞检查 |
| 编造 ID | 来源看着权威但查不到 | 强制 ID 校验，无 ID 降级 |
| 类别结论套实例 | "细菌都致病" | 强制 `scope` + 反例 |
| 载体/要素/产物混淆 | 把质粒当基因 | `entity_levels` 校验 |
| "几段"答错 | 答了错维度 | `structure_semantics` 消歧 |
| 只查网页 | 百科当权威 | 源优先级 + 证据等级 |
| 冲突被抹平 | "多数研究认为…" | 保留争议，列冲突表 |
| 高风险误导 | 给出可执行医疗/法律建议 | 免责声明 + 人工复核 |
| **假全面** | 声称"已全面考虑"但无覆盖证据 | §8 七条判据 + §14 声明 |

## 18. 最小落地清单

1. 实现内核：问题树、证据链、缺口递归、反例检查、停止规则、报告模板。
2. **加复杂度定档 + 因素空间 + 覆盖饱和** —— 这是"深"与"全"的分界，缺了它只能得到"深的局部"。
3. 领域包先做两个：科学 + 法律或金融。
4. 接三类源：领域权威库、文献库、官方来源。
5. 实现六个提示词：Planner、Question Generator、**Factor Mapper**、Extractor、Verifier、Reporter。
6. 加预算、停止规则、质量门禁。
7. 跑 12 个跨领域评测案例（含多因素与异质性难例）。
8. 通过门禁后再扩领域包。

**结论：** 通用的是**元方法**，不是内容。内核管问题形状、证据链、因素完备、范围反例、层级校验、停止与报告；领域包管实体层级、结构语义、权威源、证据分级、高风险边界。**但通用性本身是有边界的**——它依赖公开可检索证据，因此对演绎问题、主观判断、一手实验、实时决策不适用，且对不同领域的适配度是强/中/弱分层的，不是平权的。
