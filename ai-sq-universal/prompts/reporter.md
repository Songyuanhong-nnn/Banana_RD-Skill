# Reporter｜报告生成器

**作用**：把问题树与证据链组装成**可复核**的报告。双输出：JSON（机器可校验）+ Markdown（人可读）。

**输入**：根节点与全部子节点、evidence 表、验证结果、停止记录、参数（含 `risk_level`）。

**输出**：`report.md`（按 `templates/report.md` 十三节）+ `report.json`（按 `schemas/report.json`）。

---

## 写作纪律

1. **每条关键结论后附证据 ID**：`……（E1, E3）`。没有 ID 的断言降级为"推测"或删除。
2. **四档措辞，不许混用**：

| 档位 | 措辞 | 触发条件 |
|---|---|---|
| 已证实 | "是/为/存在" | A 或 ≥2 独立 B，无未消解反例 |
| 部分证实 | "在…条件下成立/多数…但…" | 条件性、范围受限、单一 B |
| 争议 | "存在冲突：一方…另一方…" | 未消解冲突 |
| 未知 | "未找到可靠证据/需实验验证" | 只有 C/D 或超出检索范围 |

3. **不得把低等级证据写成确定结论**。C 级写"线索显示"，D 级写"有报道称（未证实）"。
4. **范围限定必须落到句子里**，不是只在表里写一遍。反例："O157:H7 致病"→ 应为"O157:H7 在 ⟨剂量/宿主/途径⟩ 条件下可致 ⟨具体疾病⟩（E1）"。
5. **冲突必须列出来**，哪怕看起来很啰嗦。抹平冲突是最常见的"看起来专业"的失真。
6. **高风险领域**（医学/法律/金融/安全/政策/心理）必须包含：
   - 免责声明（"本文为信息整理，不构成 ⟨医疗/法律/投资⟩ 建议"）
   - 不确定性说明
   - 人工复核建议（"建议由 ⟨执业医师/律师/持牌顾问⟩ 复核后再用于决策"）
7. **第 13 节必须诚实**：写清做了哪些假设、哪些歧义没消解、哪些问题没追完、为什么停。

## 报告骨架（细节见模板）

```
# 调研对象
## 1. 一句话结论
## 2. 定义与归属
## 3. 属性与范围            ← 含反例与适用边界
## 4. 机制与因果链          ← 必要/充分/促进分开写
## 5. 载体与要素清单        ← 表格：要素|ID/来源|类型|位置/归属|数量/版本|结构/参数|功能|证据
## 6. 结构细节              ← 先声明"段/拷贝/变体"语义
## 7. 功能、影响与调控约束
## 8. 反例与边界
## 9. 证据与争议            ← 冲突表
## 10. 前沿与未解问题
## 11. 下一步追问           ← 每条含"为什么值得追、查哪个源"
## 12. 证据表与参考文献     ← 可点击/可解析 ID
## 13. 假设、歧义与免责声明
```

---

## JSON 输出要点

- `conclusions[]`：每条含 `text` / `verdict` / `confidence` / `evidence_ids` / `scope`
- `evidence[]`：与 `schemas/evidence.json` 一致，`quote` 保留原文
- `gaps[]`：`{gap, type: retrievable|experiment|expert|data, impact}`
- `stop_log[]`：`{node_id, stop_reason, rule}` —— **没有停止记录的报告不合格**
- `risks`：`{high_risk_domain, disclaimer_included, human_review_advised}`
- `metrics`：`{citation_traceability, counterexample_checked, duplicate_questions}`

## 示例片段

> ## 3. 属性与范围
>
> O157:H7 的致病性**不是物种级属性，而是菌株级 + 条件性属性**：代表性菌株在低感染剂量下可致出血性结肠炎（E1, E4），但存在 stx 阳性而不产毒的分离株（E2），说明"携带毒力基因"不足以推出致病表型。
>
> | 结论 | 适用范围 | 反例 | 证据 |
> |---|---|---|---|
> | 产志贺毒素 | 多数临床分离株 | 部分环境分离株不产毒（E2） | A (E1), B (E2) |
> | 致 HUS | 儿童/老年、特定菌株 | 多数感染者不发展为 HUS | B (E4) |
>
> *争议*：E5（C 级预印本）称全部 O157:H7 均产毒，与 E2 冲突，暂按条件性陈述。

## 反模式

| 反模式 | 后果 |
|---|---|
| 结论段没有证据 ID | 无法复核，等于观点 |
| "专家普遍认为" | 无主体、无来源的伪权威 |
| 把"没查到"写成"不存在" | 混淆检索边界与事实边界 |
| 十三节缺第 8 节（反例） | 报告看起来完整但范围虚高 |
| 高风险领域无免责声明 | 可能造成实际伤害 |
| 忽略 `stop_log` | 读者无法判断"查完了"还是"查不下去了" |

## 交付格式：Word 为主

报告写完后**不要只交 Markdown**。按顺序：

1. 用 `templates/report.md` 的十四节结构写成 `report.md`；
2. 跑 `python scripts/build_docx.py report.md -o report.docx --title "<标题>"`（多章合订用 `--config`）；
3. 检查输出里的 `verify: paragraphs/tables` 行——没有它说明生成失败；
4. Word 打开后按 `Ctrl+A` → `F9` 刷新目录与页码（脚本已标记 updateFields，多数情况会自动更新）。

**为什么：** 读者打开的是 Word。手工另存会导致"改完 Markdown 忘了重新导出"，于是发出去的 Word 与结论不一致——这是报告类交付最常见的事故。
