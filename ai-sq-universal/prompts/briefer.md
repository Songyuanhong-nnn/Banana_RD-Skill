# Briefer｜目的与受益方澄清器

**作用**：在开始检索之前，把"这份调研为谁而做、支撑什么决定、怎样算合格"钉死。**这一步的产出直接决定后面所有维度的取舍。**

**时机**：PLAN 之前，且**只做一次**。中途若发现目的变化，必须回来改这一节并在报告里声明。

**为什么不能跳过**：没有决定的调研会无限膨胀——因为"够不够"没有判据。写了"支撑什么决定"，深度预算、维度取舍、停止条件就都有了锚。

---

## 输出（写进报告 §0）

### 1) 目的五问

```yaml
decision: 这个调研要让谁做什么决定（若无决定，写"仅建立认知基线"）
deadline: 何时要，用于什么场合
cost_of_error: 答错谁受损、损失量级
success_criteria: 怎样算合格（必须是可判定的句子）
out_of_scope: 明确不做什么 + 理由
```

### 2) 相关方五类（缺哪类必须写"为何不适用"）

| 角色 | 必答 |
|---|---|
| 决策者 | 他要签什么？需要什么阈值与反转条件？ |
| 付费者 | 他出多少钱？在意 TCO 还是单价？ |
| 使用者 | 谁执行？需要 SOP 还是只需要结论？培训成本？ |
| 被影响者 | 谁承担后果（一线工人/社区/下游客户）？ |
| 守门人 | 谁能否决（合规/评审/上级）？他要什么依据？ |

**外扩提醒**：用户通常只说得出前两类。**使用者、被影响者、守门人必须由你主动补齐**——它们才是落地失败的高发点。

### 3) 需求外扩审计

```json
[
  {"user_asked": "用户原话", "also_needed": "还需要什么", "why": "不补会怎样", "covered": "yes|partial|pending"}
]
```

三条硬规则：
- 每条外扩必须写清"为什么必须补"；写不出的删掉（否则是加戏）。
- **目的错位**（用户问手段、真实要结果）必须挑明：可能给出更省钱的替代方案。
- 外扩项没覆盖的，进 §14 负空间，不许悄悄消失。

---

## 提问纪律（最多 3 个问题，能推断就不问）

**必问**（若缺失且无法推断）：
1. 这份东西最后要支撑什么决定？
2. 什么时候要、给谁看？
3. 有没有"必须回答的问题"清单？（有则视为**下限**，不是上限）

**不问**（可推断或可声明假设）：
- 你已经能从上下文推断的行业背景、公司规模；
- 可以列为假设并在 §13 声明的细节；
- 会拖长对话的开放式问题（"您还想了解什么"）。

---

## 自检三问

1. **删掉这份报告，哪个决定会变？** 答不出 → 目的没抓准，回到第 1 步。
2. **五类相关方里，有哪一类读完会不满意？** 答不出 → 你没替他读一遍。
3. **用户列的三条，是不是只是他想到的三条？** 是 → 外扩审计没做。

---

## 反模式

| 反模式 | 后果 |
|---|---|
| 直接开始检索，不问目的 | 精确但无用；深度无法定档 |
| 只问"你想了解什么" | 得到的是清单，不是决定 |
| 把用户清单当上限 | 漏掉决定成败的变量（预算/人员/合规） |
| 写了相关方但后面不提 | 相关方变成装饰，结论仍不服务任何人 |
| 为"显得全面"无限外扩 | 预算耗尽，主线没答完 |
