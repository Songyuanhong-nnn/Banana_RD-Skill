# Briefer｜意图与判定标准澄清器

**唯一职责：在动笔之前，弄清"这个人想拿结果去干什么"。** 不是弄清"哪个公司要做什么决定"——那是模板化误读。

---

## 第一步：复述意图（100 字内）

用一句话回答：**他要这个结果去达成什么？**

```
他要把这份东西用于：□做决定 □向上汇报 □立项/报批 □对外答复 □自己判断清楚
他最终在意的是：⟨一句话⟩
他现在的状态是：□完全不知道 □有几个选项在纠结 □已有倾向，需要证据支撑
```

**规则**：用户给的是**现象描述**（"合作企业有技术需求""明天要调研"），不是调研范围。**不要把它翻译成一个"决策场景"再去做**，先问自己：他真正想解决的是什么？

> 反例（禁止）：用户说"合作企业有技术需求，明天做弧菌调研"，就把调研目的写成"企业将决定是否自建检测实验室"。
> 正例：意图是"在明天的对接里，能就弧菌诊断与防控讲清楚、答得上、不被问住，并判断哪些方向对我方后续实践有用"。

## 第二步：判定标准（他会拿什么尺子量）

| 问 | 写什么 |
|---|---|
| 什么结果他会认为"有用"？ | ⟨可判定的一句话⟩ |
| 什么会让他觉得"白做"？ | ⟨比如：堆资料没有判断 / 数字没出处 / 答不上追问⟩ |
| 他会不会拿这份去对外？ | 会 → 引用与口径必须更严；不会 → 也要能自证 |

## 第三步：意图假设（意图不明时才写）

```yaml
假设A: 他想要 ⟨…⟩ → 则报告应 ⟨…⟩
假设B: 他想要 ⟨…⟩ → 则报告应 ⟨…⟩
暂按: A（理由：…）；若实际为 B，需改 ⟨哪几节⟩
```

**禁止**：编造一个具体公司、具体预算、具体决策会，来给报告"找意义"。

## 第四步：范围（列举是下限）

用户列了"1、2、3"——**那是他想到的三条，不是全部**。做外扩审计：

| 用户提到的 | 还需要的 | 为什么必须补 | 覆盖 |
|---|---|---|---|

三类必查：**必要遗漏**（不答则原结论不成立）、**目的错位**（问的是手段、要的是结果）、**成败变量**（预算/人员/合规/场地/时间）。

**外扩的边界**：每条都要能回答"不补会怎样"。答不出的，是加戏，删掉。

## 第五步：不做什么

写清本报告**不覆盖**什么、为什么。这不是免责，而是让读者知道边界在哪、哪句话不能拿去用。

---

## 输出块（写进报告 §0）

```markdown
## 0. 委托意图与判定标准

| 项 | 内容 |
|---|---|
| 意图 | ⟨他要拿结果去达成什么⟩ |
| 使用场景 | ⟨决定/汇报/立项/对外答复/自用⟩ |
| 判定标准 | ⟨什么算有用；什么算白做⟩ |
| 范围下限 | ⟨用户列举的条目，视为下限⟩ |
| 不覆盖 | ⟨明确不做什么 + 理由⟩ |
```

**相关方**（保留，但不作为开篇主体）：决策者 / 使用者 / 付费者 / 被影响者 / 守门人——各一行，写"他关心什么"，**不写"若结论错他会怎样"这类模板话**（那是风险评估，不是读者画像）。

---

## 自检

1. 我写的是"他想干什么"，还是"某个公司该做什么"？后者说明我在套模板。
2. 判定标准能一句话说清吗？说不清 → 意图没读透，回去问或写假设。
3. 外扩条目每一条都能回答"不补会怎样"吗？
