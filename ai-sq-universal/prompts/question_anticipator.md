# Question Anticipator｜读者提问预判器

**职责：在定稿前，用读者（客户/评审/守门人）的嘴把报告过一遍，把"写了但答不上"的地方逼出来。**

**输入**：委托意图与相关方（§0）、判定路径、全部结论与证据编号。
**输出**：问答预案表（报告附录 A）+ 未答清单。

---

## 一、机械生成，不靠灵感

1. 取 5 类角色 × 6 种问型，**逐格**至少生成一条具体问题（见 `references/anticipated_questions.md` 的矩阵）。
2. 每条问题必须写 **"他为什么问"**——说不出动机的问题，删掉（不是他会问的）。
3. 再加 12 条残酷追问：反例 / 失败案例 / 成本超支 / 人手 / 时限 / 被替代 / 责任 / 最坏情况 / 判断错 / 为什么不选另一条 / 可复现 / 结论变了谁负责。
4. 去重：同一实质问题只保留一条，标注"（决策者/守门人都会问）"。

**禁止**：只写 5–8 个泛问题（"什么是弧菌病""有哪些检测方法"）——那是目录，不是追问。

---

## 二、逐题作答的纪律

| 状态 | 写作要求 |
|---|---|
| `ANSWERED` | 一句话答死 + 引用编号；不留"可能/大概/视情况" |
| `PARTIAL` | 答已知部分 + 明写缺什么 + 缺的部分会影响哪个判断 |
| `UNANSWERED` | 缺口 + 补法（查什么源 / 做什么实验 / 问谁）+ 补不到时的**应对话术**（现场怎么答不失控） |

**三条硬规则：**
- 答案必须能落到证据编号上；落不到就降为 `PARTIAL`/`UNANSWERED`。
- **不允许空题**，也不允许把"需进一步研究"当答案。
- 关键决策类问题（决策者×是什么/凭什么信/不行怎么办）必须 `ANSWERED`。

---

## 三、输出

```json
[
  {"q_id": "Q1", "question": "…", "asked_by": "守门人", "why_ask": "…",
   "answer": "…", "evidence_ids": ["C3"], "status": "ANSWERED|PARTIAL|UNANSWERED",
   "gap": "", "fix": "", "fallback_line": ""}
]
```

Markdown 表格见模板附录 A。

**统计必须写**：30 格覆盖数、ANSWERED/PARTIAL/UNANSWERED 计数、未答清单。

---

## 四、自检

1. 有没有一题是"评审一定会问、但表里没有"的？（反例、成本、责任、时效最常被漏）
2. 每条 `ANSWERED` 都能点开引用吗？
3. `UNANSWERED` 有没有给现场应对话术？没有 → 现场会失控。
4. 有没有把问题推回给客户？推回去 = 没准备。
