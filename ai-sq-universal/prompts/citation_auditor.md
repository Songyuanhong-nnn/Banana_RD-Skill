# Citation Auditor｜引用核验器

**作用**：把"我查到过"变成"这句话确实存在于这份材料的这个位置"，并且让读者能在 30 秒内自己复核。

**为什么必须有这一步**：报告里最像证据、最不可靠的东西就是引用列表。一段成功编造的引文，读起来和真的一模一样——**唯一的区别是它定位不到**。所以核对的对象不是"来源存在吗"，而是"这句话存在吗、在哪、上下文是不是这个意思"。

**输入**：`schemas/citation.json` 格式的引用条目 + 报告中的关键结论。

**输出**：每条引用的核验结果 + 全表风险分级 + 必须降级的条目。

---

## 一、核验四问（每条引用都过）

**1. 定位得住吗？**
按 `locator` 能不能在原始材料里 30 秒内找到这句话？
- 页码/段落/条款/表格行/时间戳 —— 任一即可，但**必须是读者能照着走的路径**
- 只给首页链接、只给报告名、只给"某公众号"→ 定位失败
- 数据类来源（CSV/数据库/API）没有"句子"：locator 写 **库名 + 查询条件 + 字段 + 行/时间范围**，例如 `Wind: 板块=光伏, 字段=出货量GW, 期间=2023Q1-2024Q2, 行=汇总`

**2. 逐字吗？**
`quote` 是否与原文完全一致？检查三种常见偷改：
- **强度偷改**："相关"→"导致"、"部分"→"多数"、"可能"→"将会"
- **范围偷改**：删掉限定条件（"在 X 条件下"、"某亚组中"）
- **拼接**：把两段话合成一句"原文"

**3. 上下文支持吗？**
`context` 是否显示该句在被引用的语境里说的是同一件事？三种典型断章：
- 原文在**否定**（"并无证据表明…"），被引成肯定
- 原文在**举例反驳**，被引成作者主张
- 原文说的是**他人观点**，被引成作者结论

**4. 一手吗？**
`chain_length` 是几？若 ≥2，是否尝试回溯？回溯失败时，等级是否按**最弱一环**定（公众号转述论文 = 按公众号定，不按论文定）？

## 二、按来源类型分别处理

| 来源类型 | 能否"引用到句" | 必须怎么做 |
|---|---|---|
| 官方文件/法规/标准 | 能 | 文号 + 条款号 + 生效日；核对是否现行有效、有无修订 |
| 同行评议论文 | 能 | DOI/PMID + 页码或章节 + 原文句；区分摘要句与正文句（摘要常更绝对） |
| 上市公司披露 | 能 | 文件名 + 页码/节 + 原句；注意"管理层讨论"与"经审计数字"的证据等级不同 |
| 付费报告 | 部分能（摘录页） | 只引实际读到的页；未读全文不得引具体数字，标 `unverified` 并降级 |
| 公众号/媒体 | **只能作线索** | 定位到"第 N 段/小标题下第 N 段"；必须回溯其引述的一手；失败则标 C/D，且**不得作为关键结论唯一依据** |
| 数据/数据库 | 无句子 | 用"库名 + 查询条件 + 字段 + 期间 + 口径"定位；记录取数时间与版本 |
| 内部/访谈/闭门会 | 不能公开核验 | 标 `unverified` + 说明"不可公开复核，仅供内部参考"，不进关键结论的证据链 |
| 视频/直播 | 能（时间戳） | `timestamp` 定位 + 转写原句；说明是否为自动字幕（有错字风险） |

## 三、必查的六种作弊形态

| 作弊 | 长什么样 | 怎么抓 |
|---|---|---|
| **幽灵引文** | 来源真实、句子不存在 | 按 locator 回查原句，找不到即 fail |
| **张冠李戴** | 句子真实、但属于另一个来源 | 同一句在多个来源出现时，核实最早出处 |
| **强度漂移** | 引用没错，结论被加强 | 把 `claim` 与 `quote` 并列读，看 claim 是否超出 quote |
| **范围蒸发** | 限定条件在 claim 里消失 | 检查 quote 里的"在…条件下/某亚组/样本内"是否进了 claim |
| **二次冒充一手** | chain_length 填 1 但其实是转述 | 查 url 是否指向原文；查出版方是否为转载号 |
| **陈旧引用** | 引的是已废止条文/已更新版本 | 核对 `published_at` 与现行版本；政策类必须查修订记录 |

## 四、抽样核验（人做，机器做不了）

全表逐条回查成本太高，按风险抽样：

1. **全查**：等级 A 的引用、作为一句话结论依据的引用、政策法条类引用。
2. **抽 3 条**：随机抽 B 级引用，按 locator 回查——**必须真的打开原文，不是看标题**。
3. **专查**：所有 `chain_length >= 2` 的、所有 `verified_by: unverified` 的。

抽中的每一条，记录：能否找到原句（是/否）、上下文是否支持（是/否/部分）。**任一条"否"，则该类引用整体降级并复查同批。**

## 五、输出格式

```json
{
  "total": 24,
  "passed": 20,
  "must_downgrade": [
    {"citation_id": "C7", "reason": "locator 只到报告名，无法定位到句", "from": "B", "to": "C"},
    {"citation_id": "C11", "reason": "quote 与原文措辞不符（'多数'被引成'全部'）", "from": "A", "to": "C"}
  ],
  "chain_flags": [
    {"citation_id": "C9", "chain_length": 2, "primary_found": false, "note": "公众号转述某论文，未找到原文，按最弱一环定 C"}
  ],
  "context_failures": [
    {"citation_id": "C14", "issue": "原文为否定句（无证据表明），被引为肯定"}
  ],
  "sampling": {"sampled": 3, "found": 3, "context_ok": 2, "failed": 1, "action": "同批 B 级引用全数复查"},
  "verdict": "pass|pass_with_downgrades|fail"
}
```

`verdict=fail` 的两种情形：关键结论的唯一依据无法定位；抽样中 ≥2 条找不到原句。

## 反模式

| 反模式 | 问题 |
|---|---|
| 只核"链接能打开" | 打开了首页不等于找到了那句话 |
| 把 `verified_by` 自报为 `opened_original` 就算过 | 这是自报字段，必须靠抽样回查兜底 |
| 抽样只抽容易的 | 抽 A 级和法条（本来就是重点） |
| 找不到原句就删引用、保留结论 | 结论失去依据，必须连同结论一起降级 |
| 引用全表 100% 通过 | 通常说明核验没真做，而不是质量好 |
