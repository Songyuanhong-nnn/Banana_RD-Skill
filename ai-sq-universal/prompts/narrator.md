# Narrator｜叙事装配器

**作用**：把"问题树 + 证据表"装配成一条**有论证逻辑的线**，而不是把材料按章节摊开。

**为什么需要**：同样的证据，堆成清单读不下去，写成论证就能推动决定。**报告失效的常见原因不是数据不够，是读者读不到你的判断。**

---

## 装配结构（SCQA → 判断链）

```
S 情境：现在的事实是什么（1 段，带证据）
C 冲突：哪里不对/缺什么（1 段）
Q 问题：所以真正要回答的是什么（1 句）
A 答案：一句话结论 + Go/No-Go/条件性 Go（1-3 句）
────────────────────────────────
然后按"为什么→凭什么→边界→怎么做"展开各节：
  机制（为什么成立）
  证据（凭什么信）
  反例与边界（什么时候不成立）
  决策含义（所以做什么、监控什么）
```

---

## 四条硬规则

1. **每节首句是判断。**
   - ❌「下表列出了五种检测方法的对比。」
   - ✅「五种方法里只有 qPCR 能区分带毒株，所以放苗前筛查不能只做培养（C3）。」
2. **结论先行，支撑在后。** 不允许"铺垫三页才给结论"。
3. **每个判断紧跟证据标记**（`C#`/`E#`）。无标记 → 降级为"推测"或删除。
4. **承接**：上一节的结论是下一节的问题。**若两节互换位置不影响阅读，说明它们只是并列条目，不是论证。**

---

## 每节写作模板

```markdown
## N. ⟨本节要回答的问题，写成判断句更好⟩

⟨首句：本节结论，带证据标记⟩

⟨第二段：为什么——机制/数据/对比，带标记⟩

⟨边界：在什么条件下不成立、反例是什么⟩

⟨对本报告的相关方意味着什么：谁据此做什么⟩
```

**长度纪律**：一节只回答一个问题。一节里出现三个以上并列论点 → 拆节。

---

## 受益方嵌入（与 §0 对齐）

每个结论问三句：
- 这条对**谁**最有用？（`serves`）
- 他要据此**做什么**？（`action`）
- 信错了**代价**是什么？（`if_wrong`）

**删掉这条结论，哪个角色的哪个动作会变？** 没有动作会变 → 这条是噪音。

---

## 反模式

| 反模式 | 表现 | 修法 |
|---|---|---|
| 数据流 | 通篇"如下表""据数据显示"，没有判断 | 每节首句改写成判断 |
| 并列条目 | 14 个小节彼此无关，像词条 | 用"上一节结论→下一节问题"串起来 |
| 铺垫过长 | 背景三页，结论一句话 | 结论前置，背景压到 1 段 |
| 结论无标记 | 判断后面没有 C#/E# | 补标记或降级 |
| 相关方失联 | §0 写了五类相关方，正文从不提 | 每节末尾写"对谁意味着什么" |
| 表格代替论证 | 30 张表，没有一句话说所以呢 | 表后必有一句解读，否则删表 |
