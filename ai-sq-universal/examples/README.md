# 示例索引

这些示例的作用不是"给一份答案"，而是**让你照抄格式**：问题树怎么长、因素怎么铺、量级怎么给、反例怎么摆、覆盖度怎么交代、停止原因怎么写。

| 文件 | 演示什么 | 领域 | 关键看点 |
|---|---|---|---|
| `01-bacteriology.md` | 完整十四节报告 + 子包生效 + **因素空间** | science.bacteriology | 复杂度判 L2 → 建因素空间（6 因素/九轴覆盖/量级）；"携带基因 ≠ 表达 ≠ 致病"的反例；载体/要素分离（噬菌体 vs Stx 基因）；§14 诚实声明"覆盖不完整" |
| `02-ambiguity.md` | 量词歧义先消解 | business | "有几段"在回答前被拆成四种口径；声明假设而非硬答 |
| `03-no-answer.md` | 无答案的诚实标注 | science | "未找到"与"不存在"的区分；C 级线索不冒充结论 |
| `04-industry-direction.md` | **一条问题路径如何分叉并逐支闭合** | policy / business | 20 节点树 + 4 张详卡（平价点阈值 / 补贴到位 / 同行位置 / 决策含义）；**死胡同：补贴到位率因制度原因不可得**，降 UNKNOWN + needs_human；公众号引用必须回溯一手并定 C 级 |
| `05-equipment.md` | **设备调研：性能 / 经费 / 同行 / 市场 / 同类** | business / technology | 核心不是找数据而是**让数据可比**；可比性矩阵明确标"不可比项"；TCO 与峰值/持续口径；一条走不通的横评如何降级为"参数可比但未验证" |

## 怎么用

1. 先读 `01`，它把 `templates/report.md` 的每一节填了一遍，并且**故意留下一处覆盖缺口**（环境/外部冲击轴未查），示范"不完整也要说清楚缺哪条"。
2. 读 `02` 与 `03`，它们演示两类最容易翻车的情况：**歧义**与**查不到**。
3. 自己跑一遍质量门禁：

```bash
python scripts/quality_gate.py examples/01-bacteriology.md --complexity 2
```

应输出 `PASS`。换成 `--complexity 3` 仍然 PASS——因为示例里已包含分层矩阵与 `checked-none` 条目。若你的报告在同样检查项上失败，按提示回改，而不是降低标准。

## 关于示例中的证据 ID

`01` 中的 `PMID:00000001`、`DOI:10.1000/example.0001` 等是**合成标记**，用于展示引注格式与证据表结构；
真实运行时必须替换为本次检索到的可核验 ID。公开 accession（如 `NCBI:NC_002695.1`）可直接查证。

门禁脚本只检查**格式与结构**（有没有 ID、有没有 quote、等级是否合法、因素有没有量级），
无法判断 ID 是否真实 —— 真实性由 Extractor 的纪律保证（宁缺勿造），由人复核。
